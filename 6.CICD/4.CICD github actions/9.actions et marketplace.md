# Utiliser les actions et le Marketplace

## Objectif

Comprendre l'unité de réutilisation propre à GitHub Actions : une action appelée avec `uses` dans une étape.

## 1. Action, job et workflow

| Élément | Contenu | Appel |
| --- | --- | --- |
| Commande | Programme shell | `run` |
| Action | Fonction réutilisable, décrite par `action.yml` | `steps[*].uses` |
| Workflow réutilisable | Un ou plusieurs jobs | `jobs.<id>.uses` |
| Template de workflow | Point de départ copié dans un dépôt | Création d'un workflow |

GitLab possède des includes et composants réutilisables ; cela ne correspond pas directement au contrat d'une action GitHub, exécutée comme une étape avec ses inputs et outputs. Le Marketplace est un catalogue, pas un prérequis pour utiliser une action.

## 2. Lire une référence d'action

Dans `actions/checkout@v7`, `actions` est le propriétaire, `checkout` le dépôt et `v7` la référence Git.

- Action distante : `proprietaire/depot@reference`.
- Action locale : `./.github/actions/mon-action` après checkout.
- Sous-dossier d'un dépôt : `proprietaire/depot/chemin@reference`.

Une action locale n'a pas de suffixe `@version` : elle provient du contenu déjà récupéré.

## 3. Exemple complet

Fichier `.github/workflows/actions.yml`. Prérequis : un `README.md` à la racine.

```yaml
name: Utiliser deux actions
on:
  workflow_dispatch:
permissions:
  contents: read
jobs:
  demo:
    runs-on: ubuntu-24.04
    steps:
      - name: Recuperer le code
        uses: actions/checkout@v7
        with:
          persist-credentials: false
      - name: Verifier le fichier
        run: test -f README.md
      - name: Conserver le README
        id: archive
        uses: actions/upload-artifact@v7
        with:
          name: documentation
          path: README.md
          if-no-files-found: error
      - name: Lire un output
        env:
          ARTIFACT_ID: ${{ steps.archive.outputs.artifact-id }}
        run: |
          printf 'Identifiant artefact : %s\n' "$ARTIFACT_ID"
```

`with` fournit les inputs définis par l'action ; `id` permet de lire ses outputs. Un input inconnu n'ajoute pas une fonctionnalité : consultez le `action.yml` de la version appelée. [Checkout](https://github.com/actions/checkout), [upload-artifact](https://github.com/actions/upload-artifact)

## 4. Choisir une action

Avant adoption, vérifiez son dépôt source, ses mainteneurs, ses entrées, les permissions nécessaires et les systèmes compatibles. Le code d'une action s'exécute avec les possibilités offertes au job.

Les tags majeurs rendent les exemples lisibles, mais peuvent évoluer. Pour figer une dépendance, remplacez le tag par le SHA complet d'un commit vérifié du dépôt officiel, puis gérez ses mises à jour. Une politique d'organisation peut imposer ce format ou restreindre les actions autorisées. [Utilisation sûre des actions](https://docs.github.com/en/actions/reference/security/secure-use)

Les actions récentes peuvent nécessiter une version récente du runner autonome. Pour les actions officielles citées ici, consultez leurs notes de version avant mise à jour.

## 5. Erreurs fréquentes

| Symptôme | Cause à vérifier |
| --- | --- |
| Action introuvable | Nom, référence, droits d'accès ou politique d'organisation |
| Action locale introuvable | Checkout manquant ou mauvais chemin |
| Output vide | Mauvais `id`, nom d'output ou étape ignorée |
| Permission refusée | Permissions du job insuffisantes |
| Erreur de runtime | Runner trop ancien ou système incompatible |

# Atelier 5 : Découverte des Fonctions Terraform

## 1. Introduction

## À quoi servent les fonctions Terraform ?

Les **fonctions Terraform** servent à transformer, combiner, nettoyer ou calculer des valeurs dans le code Terraform.

Exemples simples :

```hcl
upper("dev")
```

Résultat :

```text
DEV
```

```hcl
join("-", ["app", "dev", "01"])
```

Résultat :

```text
app-dev-01
```

```hcl
length(["api", "web", "worker"])
```

Résultat :

```text
3
```

Terraform fournit des fonctions intégrées utilisables dans les expressions, avec une syntaxe du type **nom_fonction(argument1, argument2)**. Ces fonctions permettent de transformer et combiner des valeurs dans la configuration. ([HashiCorp Developer](https://developer.hashicorp.com/terraform/language/functions?utm_source=chatgpt.com "Functions - Configuration Language | Terraform"))

## 3.3 Créer le fichier main.tf

Créer le fichier **main.tf** :

```hcl
# Déclare le provider Local.
terraform {
  required_providers {
    local = {
      source  = "hashicorp/local"
      version = "~> 2.5"
    }
  }
}

# Le provider Local ne nécessite aucune configuration.
provider "local" {}

# locals centralise les valeurs calculées avec des fonctions.
locals {
  # trimspace supprime les espaces au début et à la fin.
  app_name_clean = trimspace(var.app_name)

  # lower transforme en minuscules.
  app_name_lower = lower(local.app_name_clean)

  # replace remplace les espaces par des tirets.
  app_slug = replace(local.app_name_lower, " ", "-")

  # upper transforme en majuscules.
  environment_upper = upper(var.environment)

  # max garantit un minimum de 2 instances.
  safe_instances = max(var.requested_instances, 2)

  # coalesce retourne la première valeur non nulle et non vide.
  effective_contact = coalesce(var.contact_email, "admin@example.com")

  # format construit une chaîne avec des emplacements.
  report_title = format("Rapport %s pour %s", local.app_slug, local.environment_upper)
}

# Génère un rapport avec les valeurs calculées.
resource "local_file" "base_functions_report" {
  filename = "base-functions-report.txt"

  content = <<EOT
${local.report_title}

Nom brut : ${var.app_name}
Nom nettoyé : ${local.app_name_clean}
Slug : ${local.app_slug}
Environnement : ${local.environment_upper}
Instances demandées : ${var.requested_instances}
Instances retenues : ${local.safe_instances}
Contact effectif : ${local.effective_contact}
EOT
}
```

## 3.8 Questions pédagogiques

**Quelle fonction supprime les espaces autour du nom ?**  
`trimspace`. Elle retire les espaces (et tabulations) en début et fin de chaîne. `"  Stock API  "` devient `"Stock API"`.

**Quelle fonction transforme l’environnement en majuscules ?**  
`upper`. `upper("dev")` retourne `"DEV"`.

**Pourquoi `safe_instances` vaut `2` alors que `requested_instances` vaut `1` ?**  
Parce que `max(1, 2)` retourne le plus grand des deux arguments, soit `2`. La variable a une valeur de `1`, mais `max` garantit un minimum de `2`.

**Pourquoi `effective_contact` prend la valeur `admin@example.com` ?**  
Parce que `contact_email` est une chaîne vide `""` dans le fichier `terraform.tfvars`. `coalesce` parcourt ses arguments et retourne le premier qui n’est ni `null` ni une chaîne vide. Ici `""` est ignoré et `"admin@example.com"` est retourné.

---

## 3.9 Astuces

**`trimspace` + `lower` + `replace` : la combinaison classique pour créer un identifiant technique propre**

```hcl
locals {
  # Entrée : "  Stock API  "
  slug = replace(lower(trimspace(var.app_name)), " ", "-")
  # Résultat : "stock-api"
}
```

**`format` est plus lisible que la concaténation manuelle**

```hcl
# Difficile à lire quand ça s'allonge :
title = "Rapport " + local.slug + " pour " + local.env_upper

# Avec format : plus clair et plus proche d'un printf :
title = format("Rapport %s pour %s", local.slug, local.env_upper)
# Résultat : "Rapport stock-api pour DEV"
```

---

## 3.10 Attention

`coalesce` ignore les valeurs nulles **et** les chaînes vides. Si votre logique est plus fine (par exemple : accepter une chaîne vide comme valeur valide), utilisez un ternaire à la place.

```hcl
# coalesce : "" est ignoré → retourne "admin@example.com"
contact = coalesce(var.contact_email, "admin@example.com")

# Ternaire : "" est accepté comme valeur valide si vous le souhaitez
# Ici on ne remplace que si contact_email est null
contact = var.contact_email != null ? var.contact_email : "admin@example.com"

# Ternaire : on remplace si vide OU null
contact = (var.contact_email != null && var.contact_email != "") ? var.contact_email : "admin@example.com"
```

Choisissez `coalesce` quand une chaîne vide n'a aucun sens. Choisissez le ternaire quand vous avez besoin d'une condition précise.

Créer le fichier **main.tf** :

```hcl
# Déclare le provider Local.
terraform {
  required_providers {
    local = {
      source  = "hashicorp/local"
      version = "~> 2.5"
    }
  }
}

provider "local" {}

locals {
  # length compte le nombre d'éléments.
  service_count = length(var.services)

  # element récupère un élément par index.
  first_service = element(var.services, 0)

  # keys retourne les clés d'une map.
  tag_keys = keys(var.tags)

  # values retourne les valeurs d'une map.
  tag_values = values(var.tags)

  # contains vérifie si une liste contient une valeur.
  api_enabled = contains(var.enabled_services, "api")

  # toset convertit une liste en set pour for_each.
  enabled_services_set = toset(var.enabled_services)

  # tomap force une valeur à être une map.
  normalized_tags = tomap(var.tags)

  # join transforme une liste en texte.
  services_as_text = join(", ", var.services)
}

# Crée un rapport global sur les collections.
resource "local_file" "collection_report" {
  filename = "collection-report.txt"

  content = <<EOT
Rapport collections

Nombre de services : ${local.service_count}
Premier service : ${local.first_service}
Services : ${local.services_as_text}

Clés des tags : ${join(", ", local.tag_keys)}
Valeurs des tags : ${join(", ", local.tag_values)}

API activée : ${local.api_enabled}
EOT
}

# Crée un fichier par service activé.
resource "local_file" "enabled_service_file" {
  for_each = local.enabled_services_set

  filename = "service-${each.key}.txt"

  content = <<EOT
Service activé

Nom : ${each.key}
Présent dans enabled_services : ${contains(var.enabled_services, each.key)}
EOT
}
```

## 4.9 Questions pédagogiques

**Quelle fonction retourne le nombre de services ?**  
`length`. `length(["api", "web", "worker"])` retourne `3`.

**Quelle fonction retourne les clés de la map `tags` ?**  
`keys`. `keys({ environment = "dev", owner = "formation" })` retourne `["environment", "owner"]`.

**Pourquoi utilise-t-on `toset` avec `for_each` ?**  
`for_each` exige <u>un set </u>ou <u>une map</u>, pas une liste. `toset` convertit la liste en set et garantit que chaque valeur est unique. Sans `toset`, Terraform retourne une erreur de type.

**Quelle fonction vérifie que `api` est présente dans la liste ?**  
`contains`. `contains(var.enabled_services, "api")` retourne `true` si `"api"` est présent dans la liste, `false` sinon.

## 4.10 Astuces

**`keys` et `values` pour afficher ou parcourir une map :**

```hcl
variable "tags" {
  type    = map(string)
  default = { environment = "dev", owner = "formation" }
}

locals {
  # Affiche uniquement les clés
  tag_keys   = keys(var.tags)    # → ["environment", "owner"]

  # Affiche uniquement les valeurs
  tag_values = values(var.tags)  # → ["dev", "formation"]

  # Utile pour générer une ligne par entrée dans un fichier texte
  tags_text = join("\n", [
    for k, v in var.tags : "${k} = ${v}"
  ])
  # → "environment = dev\nowner = formation"
}
```

**`toset` pour alimenter `for_each` depuis une liste :**

```hcl
variable "enabled_services" {
  type    = list(string)
  default = ["api", "web"]
}

resource "local_file" "service_file" {
  # for_each exige un set ou une map, pas une list directement
  for_each = toset(var.enabled_services)

  filename = "service-${each.key}.txt"
  content  = "Service : ${each.key}\n"
}
# Crée : service-api.txt et service-web.txt
```

**`join` pour afficher une liste dans un fichier :**

```hcl
locals {
  services_text = join(", ", ["api", "web", "worker"])
  # → "api, web, worker"

  services_lines = join("\n", ["api", "web", "worker"])
  # → "api\nweb\nworker"  (une ligne par service)
}

resource "local_file" "rapport" {
  filename = "rapport.txt"
  content  = "Services actifs : ${local.services_text}\n"
}
```

## 4.11 Attention

Un **set** n’a pas d’ordre garanti. Terraform peut traiter les éléments dans n’importe quel ordre.

```hcl
# list : ordre préservé, accès par index possible
variable "services" {
  type    = list(string)
  default = ["api", "web", "worker"]
}
# element(var.services, 0) → "api"  ✓ garanti

# set : pas d’ordre, pas d’accès par index, doublons interdits
locals {
  services_set = toset(var.services)
}
# element(local.services_set, 0) → ERREUR : element() ne fonctionne pas sur un set

# map : clé + valeur, ordre non garanti mais accès par clé possible
variable "tags" {
  type    = map(string)
  default = { env = "dev", owner = "formation" }
}
# var.tags["env"] → "dev"  ✓
```

Règle simple : utilisez `toset` uniquement pour alimenter `for_each`. Gardez une `list` quand l’ordre ou l’index compte.

## 5.12 Questions pédagogiques

**Pourquoi le fichier `intro.txt` doit-il exister avant `terraform plan` ?**  
`file("intro.txt")` est évaluée pendant la phase de planification, avant que Terraform ne crée quoi que ce soit. Si le fichier n’existe pas à ce moment, Terraform échoue immédiatement avec `Error: Invalid function argument`. Ce n’est pas comme une ressource créée pendant `apply` — c’est une lecture directe du disque lors du plan.

**Pourquoi `templatefile` est plus lisible qu’un long heredoc dans `main.tf` ?**  
Un heredoc dans `main.tf` mélange la logique Terraform et le contenu du fichier de configuration dans le même fichier. Avec `templatefile`, le template vit dans son propre fichier `.tftpl`, plus facile à modifier, à versionner et à réutiliser avec des paramètres différents.

**Quelle valeur est passée au template avec `service_count` ?**  
`length(var.services)` — c’est-à-dire le nombre d’éléments dans la liste `services`. Avec `["api", "web", "worker"]`, la valeur passée est `3`.

---

## 5.13 Astuces

**`file` pour copier un contenu statique existant :**

```hcl
locals {
  # Lit intro.txt tel quel et retourne son contenu comme une chaîne.
  intro = file("${path.module}/intro.txt")
}

resource "local_file" "copie" {
  filename = "copie.txt"
  content  = local.intro   # identique au fichier source
}
```

**`templatefile` pour injecter des variables dans un fichier de configuration :**

```hcl
# templates/app.conf.tftpl
# application_name = "${app_name}"
# environment      = "${environment}"

locals {
  config = templatefile("${path.module}/templates/app.conf.tftpl", {
    app_name    = var.app_name
    environment = var.environment
  })
}
```

**Toujours utiliser l’extension `.tftpl`** pour que l’éditeur et Terraform identifient le fichier comme un template Terraform (et non un fichier de configuration brut).

## 6.4 Créer le fichier main.tf

Créer le fichier **main.tf** :

```hcl
# Déclare le provider Local.
terraform {
  required_providers {
    local = {
      source  = "hashicorp/local"
      version = "~> 2.5"
    }
  }
}

provider "local" {}

locals {
  # Nettoie et normalise le nom du projet.
  project_slug = replace(lower(trimspace(var.project_name)), " ", "-")

  # Met l'environnement en majuscules.
  env_upper = upper(var.environment)

  # Définit un contact par défaut si contact_email est vide.
  effective_contact = coalesce(var.contact_email, "admin@example.com")

  # compact supprime les chaînes vides.
  services_without_empty = compact(var.raw_services)

  # distinct supprime les doublons.
  services_unique = distinct(local.services_without_empty)

  # sort trie la liste.
  services_sorted = sort(local.services_unique)

  # join transforme la liste en texte.
  services_text = join(", ", local.services_sorted)

  # split transforme une chaîne CSV en liste.
  ports_list = split(",", var.ports_csv)

  # format construit un identifiant lisible.
  identifier = format("%s-%s", local.project_slug, lower(var.environment))
}

resource "local_file" "advanced_functions_report" {
  filename = "${local.identifier}.txt"

  content = <<EOT

Projet normalisé : ${local.project_slug}
Environnement : ${local.env_upper}
Identifiant : ${local.identifier}

${join(", ", var.raw_services)}

Services nettoyés, uniques et triés :
${local.services_text}

Ports CSV :
${var.ports_csv}

Ports transformés en liste :
${join(" | ", local.ports_list)}
EOT
}
```

## 6.9 Questions pédagogiques

**Quelle fonction supprime les valeurs vides ?**  
`compact`. `compact(["api", "", "web"])` retourne `["api", "web"]`. Elle ne supprime que les chaînes vides `""`, pas les `null`.

**Quelle fonction supprime les doublons ?**  
`distinct`. `distinct(["api", "web", "api"])` retourne `["api", "web"]`. L'ordre de la première occurrence est conservé.

**Quelle fonction transforme une chaîne CSV en liste ?**  
`split`. `split(",", "80,443,8080")` retourne `["80", "443", "8080"]`. Le premier argument est le séparateur.

**Quelle fonction transforme une liste en chaîne ?**  
`join`. `join(" | ", ["80", "443", "8080"])` retourne `"80 | 443 | 8080"`. C'est l'inverse de `split`.

**Pourquoi utilise-t-on `locals` ici ?**  
Pour décomposer le traitement en étapes nommées et lisibles : d'abord `compact`, puis `distinct`, puis `sort`. Si on enchaîne tout en une ligne dans la ressource, le code devient difficile à relire et à déboguer.

## 6.11 Attention

Une chaîne vide `""` et `null` ne sont pas la même chose. Certaines fonctions les traitent différemment.

```hcl
variable "contact" {
  type    = string
  default = ""      # chaîne vide, pas null
}

locals {
  # coalesce : ignore "" et null → retourne le fallback
  contact_a = coalesce(var.contact, "admin@example.com")
  # Résultat : "admin@example.com"

  # compact : supprime "" dans une liste, mais pas null
  noms = compact(["api", "", "web", null])
  # Résultat : ["api", "web"]   (null est aussi supprimé ici)

  # length : compte "" comme un élément à part entière
  nb = length(["api", "", "web"])
  # Résultat : 3  (la chaîne vide compte comme un élément)
}
```

Avant d’utiliser une fonction sur une valeur optionnelle, vérifiez si elle traite `""` et `null` de la même façon ou non.

## Et les fonctions personnalisées ?

Terraform ne permet pas de définir ses propres fonctions — uniquement les fonctions intégrées au langage HCL sont disponibles.

Pour contourner cette limite, on utilise `locals` pour encapsuler une logique réutilisable à l'intérieur d'un fichier :

```hcl
locals {
  # Équivalent d'une fonction "slugify" :
  slug = replace(lower(trimspace(var.project_name)), " ", "-")
}
# Utilisation partout dans le même fichier : local.slug
```

Mais `locals` reste limité au fichier courant. Pour réutiliser une logique entre plusieurs projets, la solution Terraform est le **module** : on lui passe des variables en entrée, il retourne des outputs — exactement comme une fonction dans un autre langage.

```hcl
module "mon_module" {
  source       = "./modules/mon-module"
  project_name = var.project_name
}

output "resultat" {
  value = module.mon_module.slug
}
```

C'est précisément ce que nous allons découvrir dans le prochain atelier : **les modules Terraform**.

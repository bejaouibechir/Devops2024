# Milestone 2 — Infrastructure dynamique et conditionnelle

> **Ateliers couverts :** A5 · A6 · A7

---

## Objectif du milestone

Le projet passe d'une infrastructure fixe à une infrastructure **configurable dynamiquement**. Les VMs Azure sont créées via `for_each`, les NSG rules via `dynamic`, les comportements varient selon l'environnement, et les noms de ressources sont construits par des fonctions.

---

## Infrastructure déployée

```
Azure
└── Resource Group
    └── Virtual Network
        └── Subnet
            ├── Network Security Group
            │   ├── rule SSH (toujours présente)
            │   └── rule HTTP (uniquement si enable_http = true)
            └── VM(s) Ubuntu
                └── Public IP (uniquement si environment != "prod")
```

## Nouvelles variables

| Variable | Type | Description |
|---|---|---|
| `vms` | `map(object)` | Map des VMs à créer |
| `vm_size` | `string` | Taille Azure (ex: `Standard_B1s`) |
| `enable_http` | `bool` | Ouvre le port 80 dans le NSG |
| `admin_username` | `string` | Utilisateur admin des VMs |
| `ssh_public_key_path` | `string` | Chemin vers `id_rsa.pub` |

Exemple de variable `vms` :

```hcl
vms = {
  web = { role = "web" }
  api = { role = "api" }
}
```

## Concepts appliqués

### for_each sur les VMs

```hcl
resource "azurerm_linux_virtual_machine" "vm" {
  for_each = var.vms

  name                = "vm-${var.project}-${each.key}-${var.environment}"
  resource_group_name = azurerm_resource_group.main.name
  location            = var.location
  size                = var.vm_size
  admin_username      = var.admin_username

  admin_ssh_key {
    username   = var.admin_username
    public_key = file(var.ssh_public_key_path)  # utilise id_rsa.pub
  }
}
```

### Condition sur la Public IP

```hcl
# Pas de public IP en prod
resource "azurerm_public_ip" "vm" {
  for_each = var.environment != "prod" ? var.vms : {}
  # ...
}
```

### dynamic pour les NSG rules

```hcl
dynamic "security_rule" {
  for_each = var.enable_http ? [80] : []
  content {
    name                       = "allow-http"
    priority                   = 200
    direction                  = "Inbound"
    access                     = "Allow"
    protocol                   = "Tcp"
    destination_port_range     = tostring(security_rule.value)
    # ...
  }
}
```

### locals et fonctions pour les noms

```hcl
locals {
  name_prefix    = lower(replace("${var.project}-${var.environment}", "_", "-"))
  vm_names       = { for k, v in var.vms : k => "${local.name_prefix}-${k}" }
  common_tags    = merge({ managed_by = "terraform" }, { environment = var.environment })
}
```

## Critères de validation du milestone

- [ ] `terraform apply` crée plusieurs VMs en une seule commande
- [ ] Ajouter une VM dans `vms` → `terraform plan` montre uniquement la nouvelle VM
- [ ] Supprimer une VM dans `vms` → seule cette VM est détruite
- [ ] Avec `environment = "prod"` → aucune Public IP créée
- [ ] Avec `enable_http = false` → règle HTTP absente du NSG
- [ ] Les noms de ressources sont cohérents et en minuscules
- [ ] Connexion SSH à une VM via `id_rsa` confirmée

---

## Points de vigilance

- `for_each` nécessite des clés stables — ne pas utiliser `count` sur des ressources qui peuvent être supprimées en milieu de liste.
- La clé SSH `id_rsa` ne doit jamais être commitée. Seule `id_rsa.pub` est référencée dans le code.
- Le `file()` de `id_rsa.pub` utilise un chemin absolu ou relatif à la machine qui exécute Terraform.

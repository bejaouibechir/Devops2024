# Solution 1 — Input et fichier du dépôt

[Énoncé](../1.Exercice%201.md) · [Guide commun](../readme.md)

## 1. Fichier et workflow

Dans le dépôt d'exercice, créer `data/input.txt` avec une ligne :

```text
Amine
```

Créer `.github/workflows/exercice-1.yml` :

```yaml
name: Exercice 1 - Saisie et fichier
# Déclare les événements qui peuvent lancer ce workflow.
on:
  # Autorise le lancement manuel avec les inputs éventuellement déclarés.
  workflow_dispatch:
    # Déclare les paramètres attendus ; leur type et leurs contraintes définissent le contrat.
    inputs:
      # Définit le paramètre « prenom » et les contraintes de sa valeur.
      prenom:
        description: Prenom de 1 a 40 lettres ASCII ou traits d'union
        required: true
        type: string
        # Fournit la valeur utilisée si cet input n'est pas renseigné.
        default: Leila

# Limite les droits du GITHUB_TOKEN pour la portée du workflow ou du job.
permissions:
  # Autorise l'accès au contenu du dépôt selon le niveau indiqué.
  contents: read

# Définit les réglages par défaut des commandes run dans cette portée.
defaults:
  # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
  run:
    # Choisit l'interpréteur des commandes ; adapter leur syntaxe si ce shell change.
    shell: bash

# Déclare les jobs ; leur ordre dans le fichier ne crée pas de dépendance.
jobs:
  # Déclare le job « afficher » ; needs permet de préciser ses dépendances.
  afficher:
    # Sélectionne la machine qui exécutera ce job.
    runs-on: ubuntu-24.04
    # Arrête le traitement si sa durée dépasse ce nombre de minutes.
    timeout-minutes: 5
    # Exécute les étapes de ce job dans l'ordre sur le même runner.
    steps:
      - name: Recuperer le depot
        # Récupère les fichiers du dépôt dans le workspace du runner.
        uses: actions/checkout@v7
        # Fournit les paramètres attendus par l'action ou le workflow appelé.
        with:
          # Choisit si checkout conserve l'authentification Git pour les commandes suivantes.
          persist-credentials: false
      - name: Lire les deux prenoms
        # Injecte des variables dans les commandes de cette portée ; ce n'est pas un stockage partagé entre jobs.
        env:
          EXO_PRENOM: ${{ inputs.prenom }}
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Fixe la locale pour que les plages de caractères ASCII soient interprétées de façon prévisible.
          export LC_ALL=C
          # Contrôle le format ou le contenu attendu avant d'utiliser cette donnée.
          if [[ ! "$EXO_PRENOM" =~ ^[A-Za-z-]{1,40}$ ]]; then
            # Écrit le diagnostic sur la sortie d'erreur pour distinguer l'erreur des résultats normaux.
            echo "Prenom non conforme au contrat de cet atelier" >&2
            # Renvoie un statut non nul pour conserver l'échec dans le résultat du job.
            exit 1
          fi
          # Vérifie la présence du fichier ou de la valeur avant de poursuivre le traitement.
          if [[ ! -s data/input.txt ]]; then
            # Écrit le diagnostic sur la sortie d'erreur pour distinguer l'erreur des résultats normaux.
            echo "data/input.txt absent ou vide" >&2
            # Renvoie un statut non nul pour conserver l'échec dans le résultat du job.
            exit 1
          fi
          # Copie le fichier sur le disque du runner ; cela ne transfère rien vers la VM distante.
          cp data/input.txt /tmp/input
          # Capture la sortie de cette commande dans une variable du shell courant.
          prenom_fichier="$(cat /tmp/input)"
          # Vérifie la présence du fichier ou de la valeur avant de poursuivre le traitement.
          if [[ -z "$prenom_fichier" ]]; then
            # Écrit le diagnostic sur la sortie d'erreur pour distinguer l'erreur des résultats normaux.
            echo "Le fichier ne contient aucun prenom" >&2
            # Renvoie un statut non nul pour conserver l'échec dans le résultat du job.
            exit 1
          fi
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf 'Saisie : %s\nFichier : %s\n' "$EXO_PRENOM" "$prenom_fichier"
```

## 2. Lecture du corrigé

Le checkout apporte le fichier versionné dans l'espace de travail. `contents: read` suffit pour cette lecture et `persist-credentials: false` évite de conserver l'identifiant Git pour des commandes ultérieures. [Action checkout](https://github.com/actions/checkout)

L'expression `inputs.prenom` est affectée à une variable d'environnement. Le script utilise ensuite une expansion shell entre guillemets, sans transformer directement le texte fourni en code. Le contrat ASCII est volontairement simple ; élargir ce contrat nécessiterait d'adapter la validation.

Chaque `run` ouvre son shell. Les fichiers restent accessibles entre étapes du même job, mais un simple `export` ne persiste pas dans les suivantes. Ici, toute la lecture tient dans une étape.

## 3. Comparaison

| Jenkins | GitLab CI | GitHub Actions |
| --- | --- | --- |
| `input` peut suspendre une exécution | Input fourni à la création du pipeline | Formulaire `workflow_dispatch` avant lancement |
| Workspace de l'agent | Checkout géré par le runner selon stratégie | Action checkout explicite |
| Validation par logique Groovy | Regex d'input possible | Validation Bash de cet input texte |

## 4. Essais et résultat attendu

1. Avec les valeurs proposées : `Saisie : Leila` puis `Fichier : Amine`.
2. Avec `Jean-Paul` : réussite.
3. Avec `Jean Paul` : échec de validation.
4. Supprimer ou vider `data/input.txt`, commiter, puis relancer sur cette révision : échec explicite.

Une VM GitHub hébergée neuve est utilisée pour chaque job ; ne préparez pas `/tmp/input` manuellement sur votre ordinateur en pensant le rendre disponible au runner.

Le workflow doit exister sur la branche par défaut pour le lancement manuel. [Exécution manuelle](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/manually-run-a-workflow)

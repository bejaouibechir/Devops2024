# A2.3 – Terraform natif sur Azure avec HCP Terraform (SaaS)

**Durée estimée :** 1h30  
**Niveau :** Débutant-Intermédiaire  
**Prérequis :** Un compte Azure avec droits suffisants sur le tenant

---

## Qu'est-ce que HCP Terraform ?

HCP Terraform (HashiCorp Cloud Platform Terraform) est la version **SaaS** de Terraform. Contrairement à Terraform en local, ici :

- **Rien à installer** sur votre machine
- Le moteur Terraform tourne **dans le cloud HashiCorp**
- Le fichier de state est **géré et stocké automatiquement**
- Vous écrivez votre `main.tf`, vous le poussez, HCP l'exécute

```
Votre navigateur
    │
    ▼
HCP Terraform (SaaS)  ←── vous écrivez/uploadez votre main.tf ici
    │
    │  (appelle les APIs Azure avec les credentials que vous configurez)
    ▼
Azure (Entra ID)  ←── les ressources sont créées ici
```

---

## Étape 1 – Créer un compte HCP Terraform

1. Allez sur [https://app.terraform.io](https://app.terraform.io)
2. Cliquez **Create an account** (le plan Free est suffisant pour cet atelier)
3. Confirmez votre email
4. Créez une **Organisation** (ex : `atelier-andaluzlab`)

> L'organisation est le conteneur principal dans HCP Terraform. Tout projet y est rattaché.

---

## Étape 2 – Créer un Workspace

Un **workspace** correspond à un environnement Terraform (dev, prod…). C'est là que vos fichiers `.tf` seront exécutés.

1. Dans votre organisation, cliquez **New Workspace**
2. Choisissez **CLI-driven workflow** (vous pousserez le code depuis votre terminal ou directement via l'interface)
3. Nommez-le `atelier-a23-dev`
4. Cliquez **Create workspace**

---

## Étape 3 – Connecter HCP Terraform à Azure

HCP Terraform a besoin de **credentials Azure** pour agir sur votre tenant. On crée pour cela un **Service Principal** : un compte applicatif dans Azure AD.

### 3.1 Créer le Service Principal dans Azure

Ouvrez le portail Azure → **Azure Cloud Shell** (icône `>_` en haut) ou votre terminal local avec Azure CLI connecté, puis exécutez :

```bash
# Créer le Service Principal et noter les informations affichées
az ad sp create-for-rbac \
  --name "sp-terraform-atelier" \
  --role "User Access Administrator" \
  --scopes "/subscriptions/$(az account show --query id -o tsv)"
```

La commande retourne :

```json
{
  "appId": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx",
  "displayName": "sp-terraform-atelier",
  "password": "xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx",
  "tenant": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
}
```

> **Copiez ces 4 valeurs immédiatement** — le mot de passe ne sera plus visible ensuite.

### 3.2 Donner les droits sur Azure AD

Le rôle ci-dessus couvre les ressources Azure. Pour créer des groupes et utilisateurs dans Entra ID (Azure AD), il faut en plus accorder des droits sur l'annuaire :

```bash
# Récupérer l'object ID du Service Principal créé
az ad sp show --id <appId> --query id -o tsv
```

Puis dans le portail Azure :  
**Azure Active Directory → Rôles et administrateurs → User Administrator → Ajouter des attributions**  
→ Rechercher `sp-terraform-atelier` → Ajouter

### 3.3 Ajouter les credentials dans HCP Terraform

Dans votre workspace HCP Terraform → **Variables** → **Add variable** :

Créez ces 4 variables de type **Environment Variable** (pas Terraform variable) et marquez-les **Sensitive** :

| Variable | Valeur |
|----------|--------|
| `ARM_CLIENT_ID` | `appId` du Service Principal |
| `ARM_CLIENT_SECRET` | `password` du Service Principal |
| `ARM_TENANT_ID` | `tenant` du Service Principal |
| `ARM_SUBSCRIPTION_ID` | ID de votre subscription Azure |

> Ces variables permettent au provider `azuread` de s'authentifier automatiquement sans aucun credential dans le code.

## Étape 4 – Écrire le main.tf

Créez un fichier `main.tf` (localement dans un éditeur, ou directement dans l'interface HCP Terraform si vous utilisez le mode UI) :

```hcl
# ── Déclaration du provider AzureAD ─────────────────────────────────
terraform {
  # Indique à Terraform de stocker le state dans HCP Terraform
  cloud {
    organization = "atelier-andaluzlab"   # votre org HCP Terraform
    workspaces {
      name = "atelier-a23-dev"
    }
  }

  required_providers {
    azuread = {
      source  = "hashicorp/azuread"
      version = "~> 2.50"
    }
  }
}

provider "azuread" {
  # Les credentials viennent automatiquement des variables
  # d'environnement ARM_* configurées dans HCP Terraform
}


# ── Créer un groupe dans Azure AD ────────────────────────────────────
resource "azuread_group" "equipe_dev" {
  display_name     = "equipe-dev"
  security_enabled = true
  mail_enabled     = false
}


# ── Créer un utilisateur dans Azure AD ───────────────────────────────
resource "azuread_user" "alice" {
  user_principal_name = "alice@andaluzlab.com"   # adaptez à votre domaine
  display_name        = "Alice Dupont"
  password            = "Terraform@2024!"
  force_password_change_on_next_login = true
}


# ── Ajouter l'utilisateur au groupe ──────────────────────────────────
resource "azuread_group_member" "alice_dans_equipe_dev" {
  group_object_id  = azuread_group.equipe_dev.object_id
  member_object_id = azuread_user.alice.object_id
}


# ── Afficher les résultats ────────────────────────────────────────────
output "groupe_object_id" {
  value = azuread_group.equipe_dev.object_id
}

output "utilisateur_upn" {
  value = azuread_user.alice.user_principal_name
}
```

## Étape 5 – Lancer l'exécution depuis HCP Terraform

### Option A – Via l'interface web HCP Terraform

1. Dans votre workspace → onglet **Runs**
2. Cliquez **Start new run**
3. Uploadez votre `main.tf` (ou collez le contenu si le workspace est en mode UI)
4. HCP Terraform affiche le **plan** → vérifiez
5. Cliquez **Confirm & Apply**

### Option B – Via Terraform CLI (depuis votre machine ou Cloud Shell)

Si Terraform CLI est disponible, connectez-le à HCP :

```bash
# Connexion unique à HCP Terraform
terraform login

# Dans votre dossier contenant main.tf
terraform init    # détecte le bloc cloud {} et se connecte au workspace HCP
terraform plan    # le plan tourne sur HCP, vous voyez les logs en temps réel
terraform apply   # l'apply tourne sur HCP
```

---

## Étape 6 – Vérifier dans Azure

Après l'apply réussi, vérifiez dans le portail Azure :

**Azure Active Directory → Groupes** → vous devez voir `equipe-dev`  
**Azure Active Directory → Utilisateurs** → vous devez voir `Alice Dupont`  
**equipe-dev → Membres** → Alice doit apparaître

Ou via CLI :

```bash
az ad group show --group "equipe-dev"
az ad group member list --group "equipe-dev" --output table
```

---

## Étape 7 – Détruire les ressources

Dans HCP Terraform → workspace → **Settings → Destruction and Deletion** → **Queue destroy plan**

Terraform va lister ce qui sera supprimé → confirmez → les ressources sont supprimées d'Azure.

---

## Récapitulatif du flux HCP Terraform + Azure

```
1. Créer un compte HCP Terraform (app.terraform.io)
          ↓
2. Créer une Organisation + un Workspace
          ↓
3. Créer un Service Principal Azure
   → injecter les credentials (ARM_*) dans le workspace HCP
          ↓
4. Écrire main.tf avec le bloc cloud {} + le provider azuread
          ↓
5. Déclencher un Run (via UI ou CLI)
   → HCP exécute le plan à votre place
   → Vous confirmez l'apply
          ↓
6. Les ressources apparaissent dans Azure AD
```

## Ce que HCP Terraform gère pour vous (vs Terraform local)

| | Terraform local | HCP Terraform (SaaS) |
|---|---|---|
| Installation | À faire | Rien à installer |
| Authentification Azure | `az login` sur la machine | Variables `ARM_*` dans le workspace |
| Fichier de state | À gérer manuellement | Stocké et versionné automatiquement |
| Exécution | Sur votre machine | Dans le cloud HashiCorp |
| Historique des runs | Pas de suivi | Chaque run est loggé et consultable |

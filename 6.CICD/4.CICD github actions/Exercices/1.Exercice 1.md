# Exercice 1 — Saisie utilisateur et lecture de fichier

## Objectif

Afficher un prénom fourni au lancement et celui contenu dans un fichier. Reprise de l'[exercice GitLab 1](../../3.CICD%20gitlab-ci/Exercices/1.Exercice%201.md).

## Travail demandé

1. Suivre le [guide commun](readme.md) et créer `data/input.txt` contenant `Amine`.
2. Déclarer un workflow manuel avec un input texte `prenom`, obligatoire, par défaut `Leila`.
3. Récupérer les fichiers du dépôt.
4. Transmettre l'input au shell via `env`, puis vérifier qu'il contient de 1 à 40 lettres ASCII ou traits d'union.
5. Copier le fichier vers `/tmp/input` sur le runner et afficher les deux valeurs.
6. Faire échouer clairement le job si le fichier manque ou est vide.

## Divergences

L'input est saisi avant l'exécution, pas au milieu comme un `input` Jenkins. Le runner GitHub ne récupère pas implicitement le dépôt : utilisez `actions/checkout`. `/tmp/input` désigne le disque du runner, pas celui du poste de l'apprenant. Une saisie texte GitHub ne dispose pas du même champ `regex` que les inputs GitLab : validez-la dans le script.

## Critères et livrables

Avec `Leila`, les logs affichent `Leila` et `Amine`. Un prénom avec des espaces est rejeté selon le contrat volontairement limité de l'atelier. Un fichier absent ou vide fait échouer le workflow. Fournir YAML, fichier et traces des essais.

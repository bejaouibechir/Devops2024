# Mettre les dépendances en cache

## Objectif

Accélérer les exécutions répétées sans utiliser le cache comme contrat de livraison.

## 1. Comparaison avec GitLab

GitLab possède également `cache`. Dans GitHub, `actions/cache` ou les options des actions de configuration gèrent restauration et sauvegarde.

| Besoin | Mécanisme |
| --- | --- |
| Réutiliser des dépendances téléchargeables | Cache |
| Transmettre un livrable précis à un autre job | Artefact |
| Distribuer une version durable | Registre ou release |

Un cache peut manquer ou être évincé. Le build doit rester correct sans lui. [Cache et artefacts](https://docs.github.com/en/actions/concepts/workflows-and-actions/dependency-caching)

## 2. Atelier autonome

Créez `cache-input.txt` à la racine avec le contenu `version=1`. Puis créez `.github/workflows/cache.yml` :

```yaml
name: Comprendre le cache
on:
  workflow_dispatch:
permissions:
  contents: read
jobs:
  demo:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v7
        with:
          persist-credentials: false
      - run: test -f cache-input.txt
      - name: Restaurer le cache
        id: cache
        uses: actions/cache@v6
        with:
          path: .cache-demo
          key: demo-v1-${{ runner.os }}-${{ hashFiles('cache-input.txt') }}
      - name: Recalculer si absent
        if: ${{ steps.cache.outputs.cache-hit != 'true' }}
        run: |
          mkdir -p .cache-demo
          printf 'Calcul initial du run %s\n' "$GITHUB_RUN_ID" > .cache-demo/result.txt
      - run: cat .cache-demo/result.txt
```

Lancez deux fois sans modifier le fichier d'entrée. Le second run devrait retrouver le premier résultat si le cache a été enregistré et reste disponible. Modifiez `cache-input.txt` : la clé change, donc le calcul reprend.

`cache-hit` est une chaîne. Une correspondance exacte vaut `'true'`. Avec `restore-keys`, une restauration partielle peut fournir des fichiers tout en laissant ce résultat faux : une installation de dépendances doit alors compléter ce qui manque.

Une entrée existante n'est pas modifiée sur place ; changer la clé permet de créer un nouvel état. [Action cache](https://github.com/actions/cache)

## 3. Application à Maven

Pour un projet Maven, la fiche [artefacts](7.artefact.md) utilise `setup-java` avec `cache: maven`. Cela évite de recopier une configuration de cache manuelle pour le même répertoire.

Le cache ne dispense pas d'exécuter Maven pour vérifier et résoudre les dépendances. Ne conditionnez pas tout le build à `cache-hit`.

## 4. Portée et confiance

L'accès dépend notamment de la branche, de la clé et de la version de cache. Une PR peut restaurer des caches accessibles dans son contexte ; n'y placez jamais de clé SSH, jeton ou fichier de configuration contenant un secret.

Les versions récentes offrent aussi des contrôles d'accès plus fins. Avant d'en dépendre, vérifiez leur disponibilité et le comportement du service utilisé. Une clé difficile à deviner n'est pas une règle d'autorisation.

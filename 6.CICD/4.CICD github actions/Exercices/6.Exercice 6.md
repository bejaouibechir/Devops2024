# Exercice 6 — Diagnostics sur une VM par SSH

## Objectif

Depuis un runner GitHub, afficher l'utilisateur, le nom d'hôte, la disponibilité et l'espace disque d'une VM. Reprise de l'[exercice GitLab 6](../../3.CICD%20gitlab-ci/Exercices/6.Exercice%206.md).

## Travail demandé

1. Réaliser la [préparation SSH](readme.md#préparation-ssh-pour-les-exercices-6-à-8).
2. Restreindre le workflow à un lancement manuel sur `main` et utiliser `atelier-ssh`.
3. Valider hôte, compte et port ; matérialiser les deux secrets avec des droits restrictifs.
4. Exécuter `whoami`, `hostname`, `uptime` et `df -h` sur la VM avec contrôle strict de sa clé d'hôte.
5. Conserver le code d'échec de SSH et nettoyer les fichiers secrets locaux.

## Divergences et critères

Les secrets GitHub contiennent du texte, pas un chemin de variable File GitLab. Aucun plugin SSH Jenkins n'est nécessaire : on utilise le client OpenSSH du runner. Ne pas confondre les informations du runner avec celles du serveur.

Fournir une exécution réussie, puis un essai avec un port incorrect ou un fichier known_hosts ne correspondant pas à la VM. Le second doit échouer sans désactiver la vérification d'identité. Aucun sudo ni secret dans les logs ou artefacts.

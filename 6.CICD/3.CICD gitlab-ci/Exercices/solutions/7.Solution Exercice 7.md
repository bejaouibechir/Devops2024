# Solution 7 — Génération, transfert et exécution d'un script

[Énoncé](../7.Exercice%207.md) · [Préparation SSH commune](../readme.md#prérequis-ssh-pour-les-exercices-6-à-8)

## 1. Configuration complète

La VM doit avoir Bash et un `/tmp` accessible au compte dédié. Le script et son rapport sont créés dans le même job.

```yaml
workflow:
  rules:
    - if: '$CI_PIPELINE_SOURCE == "web" && $CI_COMMIT_REF_PROTECTED == "true"'
    - when: never

default:
  image: alpine:3.22

script_distant:
  timeout: 5 minutes
  before_script:
    - apk add --no-cache openssh-client
    - |
      set -eu
      : "${SSH_HOST:?Configurer SSH_HOST}"
      : "${SSH_USER:?Configurer SSH_USER}"
      : "${SSH_PRIVATE_KEY:?Configurer la variable File SSH_PRIVATE_KEY}"
      : "${SSH_KNOWN_HOSTS:?Configurer la variable File SSH_KNOWN_HOSTS}"
      test -s "$SSH_PRIVATE_KEY"
      test -s "$SSH_KNOWN_HOSTS"
      chmod 600 "$SSH_PRIVATE_KEY"
  script:
    - |
      set -eu
      cat > infos.sh <<'SCRIPT'
      #!/usr/bin/env bash
      set -euo pipefail
      printf 'Date : %s\n' "$(date -u '+%Y-%m-%dT%H:%M:%SZ')"
      printf 'Utilisateur : %s\n' "$(whoami)"
      printf 'Machine : %s\n' "$(hostname)"
      SCRIPT

      case "$CI_PROJECT_ID:$CI_JOB_ID" in
        *[!0-9:]*|:*)
          echo "Identifiants CI inattendus" >&2
          exit 1
          ;;
      esac
      remote_dir="/tmp/gitlab-ci-${CI_PROJECT_ID}-${CI_JOB_ID}"

      ssh_ci() {
        ssh -T \
          -i "$SSH_PRIVATE_KEY" \
          -p "${SSH_PORT:-22}" \
          -o BatchMode=yes \
          -o IdentitiesOnly=yes \
          -o StrictHostKeyChecking=yes \
          -o "UserKnownHostsFile=$SSH_KNOWN_HOSTS" \
          -o ConnectTimeout=10 \
          "${SSH_USER}@${SSH_HOST}" "$@"
      }

      printf 'Repertoire temporaire distant : %s\n' "$remote_dir"
      ssh_ci "umask 077; mkdir '$remote_dir'"

      scp -i "$SSH_PRIVATE_KEY" \
        -P "${SSH_PORT:-22}" \
        -o BatchMode=yes \
        -o IdentitiesOnly=yes \
        -o StrictHostKeyChecking=yes \
        -o "UserKnownHostsFile=$SSH_KNOWN_HOSTS" \
        -o ConnectTimeout=10 \
        infos.sh "${SSH_USER}@${SSH_HOST}:${remote_dir}/infos.sh"

      ssh_ci "chmod 700 '$remote_dir/infos.sh' && '$remote_dir/infos.sh'" \
        > execution-distante.log
      cat execution-distante.log
      ssh_ci "rm -- '$remote_dir/infos.sh' && rmdir -- '$remote_dir'"
  artifacts:
    when: always
    paths:
      - infos.sh
      - execution-distante.log
    expire_in: 1 day
```

## 2. Pourquoi le script affiche-t-il la VM ?

Le délimiteur `<<'SCRIPT'` est cité : le shell du runner ne remplace pas les expressions `$(...)`. Elles restent dans le fichier et sont évaluées lorsque le serveur lance le script.

La fonction `ssh_ci` regroupe les mêmes options pour toutes les commandes distantes. SCP utilise `-P` pour le port, tandis que SSH utilise `-p`. [Manuel SCP](https://man.openbsd.org/scp)

Le répertoire est dérivé des identifiants numériques CI. `mkdir` échoue si ce chemin existe déjà ; l'exemple ne réutilise pas silencieusement un répertoire préexistant.

## 3. Artefacts et statut d'erreur

La sortie est redirigée vers un rapport, puis affichée. Aucun pipe vers `tee` ne risque de masquer le statut de SSH.

`artifacts:when:always` permet de récupérer les fichiers créés même après un échec ordinaire. Si l'erreur survient avant leur création, GitLab peut signaler leur absence ; ce n'est pas la cause initiale à corriger.

La liste de chemins exclut la clé et le fichier des hôtes connus. [Artefacts de jobs](https://docs.gitlab.com/ci/jobs/job_artifacts/)

## 4. Nettoyage et échec volontaire

Après un succès, seul le script créé par cet atelier est retiré, puis son dossier vide est supprimé avec `rmdir`.

Si le transfert ou le script échoue, le job conserve l'échec et peut laisser le répertoire distant. Son chemin exact figure dans les logs. Inspectez-le avant nettoyage manuel ; ne supprimez pas globalement les répertoires `/tmp/gitlab-ci-*`.

Ajoutez temporairement `false` dans le script généré, avant la dernière ligne. Le job doit échouer et le rapport peut ne contenir que les premières sorties.

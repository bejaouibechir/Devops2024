# Exercice 1 — Input utilisateur et lecture d'un fichier

## Objectif

Afficher un prénom fourni au lancement et un autre lu depuis un fichier accessible au job. Adaptation de l'[exercice Jenkins 1](../../2.CICD%20jenkins/Exercices/1.Exercice%201.md).

## Prérequis

Suivez le [guide commun](readme.md). Ajoutez au dépôt `data/input.txt` contenant une seule ligne, par exemple `Amine`.

## Travail demandé

1. Déclarer un input de pipeline `prenom`, avec une valeur par défaut.
2. Autoriser le lancement depuis **New pipeline**.
3. Transmettre l'input à une variable du job, puis le lire dans le shell.
4. Vérifier que `data/input.txt` existe et n'est pas vide.
5. Copier ce fichier vers `/tmp/input` **dans le conteneur du job**.
6. Lire `/tmp/input` et afficher séparément les deux prénoms.
7. Faire échouer le job avec un message compréhensible si le fichier manque ou est vide.

## Divergences à prendre en compte

Le `/tmp/input` de votre poste ou d'un ancien agent Jenkins n'existe pas automatiquement dans un runner Docker. Le fichier versionné sert ici à rendre l'atelier reproductible.

L'input est saisi avant création du pipeline : aucun équivalent d'une boîte `input` Jenkins ne s'ouvre au milieu du script. N'utilisez pas `read` pour attendre le clavier dans le job.

## Résultats et essais attendus

| Essai | Résultat |
| --- | --- |
| `prenom=Leila`, fichier `Amine` | Les deux valeurs sont affichées |
| Fichier absent | Job en échec avec diagnostic |
| Fichier vide | Job en échec avec diagnostic |
| Nouveau pipeline | Nouvelle préparation du fichier dans son propre job |

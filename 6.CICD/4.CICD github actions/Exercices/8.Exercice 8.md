# Exercice 8 — Ansible depuis le runner GitHub

## Objectif

Générer un inventaire et un playbook, puis utiliser Ansible pour lire date, utilisateur et nom de la VM. Reprise de l'[exercice GitLab 8](../../3.CICD%20gitlab-ci/Exercices/8.Exercice%208.md).

## Travail demandé

1. Préparer l'[environnement SSH](readme.md#préparation-ssh-pour-les-exercices-6-à-8).
2. Installer une version compatible de Python et Ansible sur le runner.
3. Générer `inventory.ini` à partir des paramètres validés sans y inclure la clé privée.
4. Générer `infos.yml` avec trois commandes de lecture, `register` et une tâche `debug`.
5. Déclarer ces lectures avec `changed_when: false` et sans élévation de privilèges.
6. Vérifier la syntaxe puis exécuter le playbook avec contrôle strict de l'hôte SSH.
7. Publier uniquement l'inventaire et le playbook pendant un jour et nettoyer les secrets.

## Divergences et critères

Ansible reste une CLI : il n'existe pas de traduction de ses modules en clés GitHub Actions. Ce qui change par rapport à GitLab est la préparation du runner, l'accès aux secrets et la publication des fichiers. Aucune installation d'Ansible n'est requise sur la VM, mais un Python compatible y est nécessaire.

Résultat attendu : `failed=0`, `unreachable=0`, `changed=0`, avec les trois sorties visibles. Tester un hôte invalide dans la génération, puis un problème SSH réel. Ne pas confondre `--syntax-check` et une connexion réussie.

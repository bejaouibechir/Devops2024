# Solution 8 — Ansible comme outil du runner

[Énoncé](../8.Exercice%208.md) · [Préparation SSH commune](../readme.md#prérequis-ssh-pour-les-exercices-6-à-8)

## 1. Architecture et versions

Le conteneur du job est le nœud de contrôle ; la VM est un hôte géré. Ansible n'a pas besoin d'être installé sur la VM.

L'exemple utilise Python 3.12 et la branche `ansible-core` 2.21, qui accepte Python 3.9 à 3.14 sur les cibles selon la documentation consultée. La VM doit posséder `/usr/bin/python3`. [Compatibilité Ansible](https://docs.ansible.com/projects/ansible/latest/reference_appendices/release_and_maintenance.html)

La contrainte `>=2.21,<2.22` reçoit les correctifs de cette branche. Pour figer un environnement de formation, construisez une image contrôlée avec une version corrective et un digest précis après validation.

## 2. Configuration complète

```yaml
# Décide si GitLab crée un pipeline pour cet événement.
workflow:
  # Évalue les règles dans l'ordre pour inclure ou exclure le pipeline ou le job avant l'exécution.
  rules:
    # Teste cette expression lors de la création du pipeline, avant tout calcul par script.
    - if: '$CI_PIPELINE_SOURCE == "web" && $CI_COMMIT_REF_PROTECTED == "true"'
    # Exclut ce pipeline ou ce job lorsque cette règle est retenue.
    - when: never

# Applique ces réglages aux jobs qui ne les redéfinissent pas.
default:
  # Choisit l'image utilisée par l'exécuteur compatible ; un exécuteur Shell ne la lance pas.
  image: python:3.12-slim-bookworm

# Déclare le job « collecter_informations » et sa configuration propre.
collecter_informations:
  # Limite la durée du job ; ne crée ni attente ni nouvelle tentative.
  timeout: 10 minutes
  # Définit les variables de cette portée ; les valeurs de projet ou de pipeline peuvent être prioritaires.
  variables:
    ANSIBLE_HOST_KEY_CHECKING: "True"
    ANSIBLE_NOCOLOR: "1"
  # Prépare le job avant ses commandes principales, dans le même contexte de shell.
  before_script:
    # Actualise la liste des paquets disponibles avant leur installation.
    - apt-get update
    # Installe les outils requis dans l'environnement d'exécution du job.
    - apt-get install -y --no-install-recommends openssh-client ca-certificates
    # Installe les dépendances Python avec la contrainte de version indiquée pour cet atelier.
    - python -m pip install --no-cache-dir 'ansible-core>=2.21,<2.22'
    - |
      # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie.
      set -eu
      # Interrompt le script si cette configuration obligatoire est absente ou vide.
      : "${SSH_HOST:?Configurer SSH_HOST}"
      : "${SSH_USER:?Configurer SSH_USER}"
      : "${SSH_PRIVATE_KEY:?Configurer la variable File SSH_PRIVATE_KEY}"
      : "${SSH_KNOWN_HOSTS:?Configurer la variable File SSH_KNOWN_HOSTS}"
      # Exige un fichier existant et non vide avant de l'utiliser.
      test -s "$SSH_PRIVATE_KEY"
      test -s "$SSH_KNOWN_HOSTS"
      # Applique les permissions indiquées au fichier ou au répertoire avant son utilisation.
      chmod 600 "$SSH_PRIVATE_KEY"
      # Affiche la version d'Ansible effectivement installée sur le runner.
      ansible-playbook --version
  # Exécute ces commandes dans l'ordre sur le runner attribué au job.
  script:
    - |
      # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie.
      set -eu
      # Exécute ce programme Python localement pour valider les données et préparer les fichiers du job.
      python - <<'PY'
      import os
      import re
      from pathlib import Path

      # Lit les paramètres transmis au programme par l'environnement du job.
      host = os.environ["SSH_HOST"]
      user = os.environ["SSH_USER"]
      port_text = os.environ.get("SSH_PORT", "22")
      # Refuse une valeur qui pourrait sortir du format prévu ou modifier la structure de l'inventaire.
      if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9.-]*", host):
          raise SystemExit("Utiliser un nom DNS ou une IPv4 simple pour cet atelier")
      if not re.fullmatch(r"[a-z_][a-z0-9_-]*", user):
          raise SystemExit("Nom de compte SSH non conforme a cet atelier")
      if not port_text.isdecimal() or not 1 <= int(port_text) <= 65535:
          raise SystemExit("Port SSH invalide")
      # Construit la ligne INI de l'hôte avec son compte, son port et son interpréteur Python.
      inventory = (
          "[remote]\n"
          f"atelier ansible_host={host} ansible_user={user} "
          f"ansible_port={int(port_text)} ansible_python_interpreter=/usr/bin/python3\n"
      )
      # Enregistre l'inventaire en UTF-8 pour l'appel Ansible suivant.
      Path("inventory.ini").write_text(inventory, encoding="utf-8")
      PY

      # Écrit le playbook Ansible ; les expressions Jinja restent intactes jusqu'à l'exécution d'Ansible.
      cat > infos.yml <<'PLAYBOOK'
      ---
      - name: Collecter des informations de la VM
        # Sélectionne le groupe d'hôtes défini dans l'inventaire.
        hosts: remote
        # Active ou désactive la collecte automatique des informations système au début du play.
        gather_facts: false
        # Choisit si les tâches demandent une élévation de privilèges.
        become: false
        # Exécute ces tâches dans l'ordre sur les hôtes sélectionnés.
        tasks:
          - name: Lire la date
            # Exécute cette commande sur la cible sans passer par un shell.
            ansible.builtin.command: date -u
            # Conserve le résultat de la tâche pour le réutiliser, notamment sa sortie stdout.
            register: date_result
            # Définit si cette lecture doit être comptée comme une modification de la machine.
            changed_when: false

          - name: Lire le compte courant
            # Exécute cette commande sur la cible sans passer par un shell.
            ansible.builtin.command: whoami
            # Conserve le résultat de la tâche pour le réutiliser, notamment sa sortie stdout.
            register: user_result
            # Définit si cette lecture doit être comptée comme une modification de la machine.
            changed_when: false

          - name: Lire le nom de la machine
            # Exécute cette commande sur la cible sans passer par un shell.
            ansible.builtin.command: hostname
            # Conserve le résultat de la tâche pour le réutiliser, notamment sa sortie stdout.
            register: host_result
            # Définit si cette lecture doit être comptée comme une modification de la machine.
            changed_when: false

          - name: Afficher les informations
            # Affiche explicitement les valeurs collectées dans le résultat du playbook.
            ansible.builtin.debug:
              msg:
                - "Date : {{ date_result.stdout }}"
                - "Utilisateur : {{ user_result.stdout }}"
                - "Machine : {{ host_result.stdout }}"
      PLAYBOOK

      # Prépare les options communes de connexion, transmises ensuite au client SSH par Ansible.
      ssh_options="-o BatchMode=yes -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes"
      ssh_options="$ssh_options -o UserKnownHostsFile='$SSH_KNOWN_HOSTS'"
      ssh_options="$ssh_options -o ConnectTimeout=10"

      # Vérifie la syntaxe du playbook ; ce contrôle ne prouve pas que la connexion SSH fonctionne.
      ansible-playbook -i inventory.ini infos.yml --syntax-check
      # Exécute le playbook sur les hôtes de l'inventaire avec les options d'authentification indiquées.
      ansible-playbook -i inventory.ini infos.yml \
        --private-key "$SSH_PRIVATE_KEY" \
        --ssh-common-args "$ssh_options"
  # Conserve les fichiers ou rapports du job pour consultation ou transmission.
  artifacts:
    # Définit selon quel résultat du job les artefacts seront collectés.
    when: always
    # Sélectionne les fichiers du workspace à publier comme artefacts.
    paths:
      - inventory.ini
      - infos.yml
    # Fixe la durée de conservation demandée pour ces artefacts.
    expire_in: 1 day
```

## 3. Pourquoi générer l'inventaire avec validation ?

Un inventaire INI interprète les espaces et les paramètres. La validation limite ici le nom d'hôte, le compte et le port pour éviter d'y injecter des champs supplémentaires. Elle exclut volontairement les adresses IPv6 et certains formats de comptes.

La clé privée est passée à la CLI, pas écrite dans l'inventaire ni copiée en `id_rsa`. Les fichiers publiés ne contiennent pas de clé, mais l'inventaire révèle l'adresse du serveur : gardez l'accès aux artefacts adapté à votre atelier. [Inventaires Ansible](https://docs.ansible.com/projects/ansible/latest/inventory_guide/intro_inventory.html)

## 4. Exécution et affichage

Les tâches utilisent `ansible.builtin.command` parce que ces commandes n'ont besoin d'aucune fonctionnalité de shell. `register` capture leur résultat ; `debug` affiche explicitement les trois sorties.

`changed_when: false` décrit ces lectures comme non modificatrices. `become: false` évite une élévation inutile. [Module command](https://docs.ansible.com/projects/ansible/latest/collections/ansible/builtin/command_module.html)

La syntaxe est vérifiée avant la connexion. Le second appel réalise le travail distant. Un succès doit produire `failed=0`, `unreachable=0` et `changed=0`.

## 5. Diagnostic

| Symptôme | Point à contrôler |
| --- | --- |
| Installation impossible | Accès au registre, aux paquets Debian et Python |
| `UNREACHABLE` | Réseau, compte, clé, clés d'hôte et port |
| Interpréteur Python absent | Installation et chemin `/usr/bin/python3` sur la VM |
| Refus de l'inventaire généré | Format de `SSH_HOST`, `SSH_USER` ou `SSH_PORT` |
| Valeurs invisibles | Présence de la tâche `debug` et réussite des commandes |

## Validation attendue

Les informations proviennent de la VM et le récapitulatif ne contient aucun échec. Le playbook doit encore être validé avec Ansible et exécuté dans votre environnement ; aucune installation Ansible ni connexion à une VM n'a été effectuée pendant la rédaction.

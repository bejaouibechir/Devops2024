# Solution 8 — Ansible depuis le runner

[Énoncé](../8.Exercice%208.md) · [Préparation SSH](../readme.md#préparation-ssh-pour-les-exercices-6-à-8)

## 1. Workflow complet

Configurer l'environnement `atelier-ssh` et ses cinq valeurs avant l'exécution. Les exemples visent un lancement manuel sur `main` et un runner GitHub hébergé. OpenSSH et Python 3 sont présents sur l'image Ubuntu choisie ; l'étape de préparation contrôle leur disponibilité.

Créer `.github/workflows/exercice-8.yml` :

```yaml
name: Exercice 8 - Ansible depuis le runner
on:
  workflow_dispatch:

permissions:
  contents: read
defaults:
  run:
    shell: bash

jobs:
  collecter_informations:
    if: ${{ github.ref == 'refs/heads/main' }}
    environment: atelier-ssh
    runs-on: ubuntu-24.04
    timeout-minutes: 10
    env:
      SSH_HOST: ${{ vars.SSH_HOST }}
      SSH_USER: ${{ vars.SSH_USER }}
      SSH_PORT: ${{ vars.SSH_PORT || '22' }}
      ANSIBLE_HOST_KEY_CHECKING: "True"
      ANSIBLE_NOCOLOR: "1"
    steps:
      - name: Installer Python
        uses: actions/setup-python@v7
        with:
          python-version: '3.12'
      - name: Installer Ansible
        run: |
          python -m pip install --no-cache-dir 'ansible-core>=2.21,<2.22'
          ansible-playbook --version
      - name: Preparer les fichiers SSH
        env:
          EXO_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          EXO_KNOWN_HOSTS: ${{ secrets.SSH_KNOWN_HOSTS }}
        run: |
          set -euo pipefail
          command -v ssh
          command -v scp
          python3 - <<'PY'
          import os
          import re
          host = os.environ["SSH_HOST"]
          user = os.environ["SSH_USER"]
          port = os.environ["SSH_PORT"]
          if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9.-]*", host):
              raise SystemExit("Hote invalide : utiliser DNS ou IPv4 simple")
          if not re.fullmatch(r"[a-z_][a-z0-9_-]*", user):
              raise SystemExit("Compte SSH invalide pour cet atelier")
          if not re.fullmatch(r"[0-9]{1,5}", port) or not 1 <= int(port) <= 65535:
              raise SystemExit("Port invalide")
          PY
          : "${EXO_PRIVATE_KEY:?Configurer SSH_PRIVATE_KEY}"
          : "${EXO_KNOWN_HOSTS:?Configurer SSH_KNOWN_HOSTS}"
          umask 077
          mkdir -p "$RUNNER_TEMP/atelier-ssh"
          chmod 700 "$RUNNER_TEMP/atelier-ssh"
          printf '%s\n' "$EXO_PRIVATE_KEY" > "$RUNNER_TEMP/atelier-ssh/key"
          printf '%s\n' "$EXO_KNOWN_HOSTS" > "$RUNNER_TEMP/atelier-ssh/known_hosts"
          chmod 600 "$RUNNER_TEMP/atelier-ssh/key" "$RUNNER_TEMP/atelier-ssh/known_hosts"
          {
            printf 'SSH_PRIVATE_KEY_FILE=%s\n' "$RUNNER_TEMP/atelier-ssh/key"
            printf 'SSH_KNOWN_HOSTS_FILE=%s\n' "$RUNNER_TEMP/atelier-ssh/known_hosts"
          } >> "$GITHUB_ENV"
      - name: Generer et executer Ansible
        run: |
          set -eu
          python - <<'PY'
          import os
          import re
          from pathlib import Path

          host = os.environ["SSH_HOST"]
          user = os.environ["SSH_USER"]
          port_text = os.environ.get("SSH_PORT", "22")
          if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9.-]*", host):
              raise SystemExit("Utiliser un nom DNS ou une IPv4 simple pour cet atelier")
          if not re.fullmatch(r"[a-z_][a-z0-9_-]*", user):
              raise SystemExit("Nom de compte SSH non conforme a cet atelier")
          if not port_text.isdecimal() or not 1 <= int(port_text) <= 65535:
              raise SystemExit("Port SSH invalide")
          inventory = (
              "[remote]\n"
              f"atelier ansible_host={host} ansible_user={user} "
              f"ansible_port={int(port_text)} ansible_python_interpreter=/usr/bin/python3\n"
          )
          Path("inventory.ini").write_text(inventory, encoding="utf-8")
          PY

          cat > infos.yml <<'PLAYBOOK'
          ---
          - name: Collecter des informations de la VM
            hosts: remote
            gather_facts: false
            become: false
            tasks:
              - name: Lire la date
                ansible.builtin.command: date -u
                register: date_result
                changed_when: false

              - name: Lire le compte courant
                ansible.builtin.command: whoami
                register: user_result
                changed_when: false

              - name: Lire le nom de la machine
                ansible.builtin.command: hostname
                register: host_result
                changed_when: false

              - name: Afficher les informations
                ansible.builtin.debug:
                  msg:
                    - "Date : {{ date_result.stdout }}"
                    - "Utilisateur : {{ user_result.stdout }}"
                    - "Machine : {{ host_result.stdout }}"
          PLAYBOOK

          ssh_options="-o BatchMode=yes -o IdentitiesOnly=yes -o StrictHostKeyChecking=yes"
          ssh_options="$ssh_options -o UserKnownHostsFile='$SSH_KNOWN_HOSTS_FILE'"
          ssh_options="$ssh_options -o ConnectTimeout=10"

          ansible-playbook -i inventory.ini infos.yml --syntax-check
          ansible-playbook -i inventory.ini infos.yml \
            --private-key "$SSH_PRIVATE_KEY_FILE" \
            --ssh-common-args "$ssh_options"
      - name: Conserver les fichiers de travail
        if: ${{ always() }}
        uses: actions/upload-artifact@v7
        with:
          name: exercice-8-${{ github.run_id }}-${{ github.run_attempt }}
          path: |
            inventory.ini
            infos.yml
          retention-days: 1
          if-no-files-found: warn
      - name: Nettoyer les fichiers secrets locaux
        if: ${{ always() }}
        run: |
          set -euo pipefail
          rm -f -- "$RUNNER_TEMP/atelier-ssh/key" "$RUNNER_TEMP/atelier-ssh/known_hosts"
          if [[ -d "$RUNNER_TEMP/atelier-ssh" ]]; then
            rmdir -- "$RUNNER_TEMP/atelier-ssh"
          fi
```

## 2. Versions et rôle du runner

Le runner est le nœud de contrôle Ansible ; la VM est la cible. `setup-python` sélectionne Python 3.12, puis pip installe la branche `ansible-core` 2.21. Cette branche accepte Python 3.9 à 3.14 sur la cible selon la documentation consultée. Le chemin `/usr/bin/python3` doit exister sur la VM. [Setup Python](https://github.com/actions/setup-python), [compatibilité Ansible](https://docs.ansible.com/projects/ansible/latest/reference_appendices/release_and_maintenance.html)

La plage `>=2.21,<2.22` reçoit les correctifs de la branche. Une formation devant être strictement reproductible pourra figer une version corrective validée et ses dépendances.

Le corrigé GitLab utilisait une image de conteneur Python. Ici les étapes préparent directement le runner Ubuntu ; copier seulement la clé GitLab `image` ne configurerait pas ce job.

## 3. Inventaire, playbook et identité SSH

Le générateur vérifie les formats avant d'écrire l'inventaire. Il accepte DNS/IPv4 et un nom de compte Linux simple ; IPv6 nécessiterait une adaptation. Les paramètres ne peuvent pas injecter des champs supplémentaires dans la ligne INI.

Le playbook utilise `command`, capture chaque résultat avec `register` et l'affiche avec `debug`. Les trois commandes lisent des informations ; `changed_when: false` évite de les compter comme modifications. `become: false` évite une élévation inutile. [Module command](https://docs.ansible.com/projects/ansible/latest/collections/ansible/builtin/command_module.html)

La clé est fournie à la CLI et n'apparaît pas dans l'inventaire. Le contrôle des clés d'hôte reste actif. Le premier appel `--syntax-check` ne prouve pas que SSH fonctionne ; le second appel réalise la connexion.

## 4. Résultats attendus et artefacts

Le récapitulatif attendu contient `failed=0`, `unreachable=0` et `changed=0`. Les trois sorties doivent apparaître dans la tâche `debug`.

Les artefacts incluent seulement `inventory.ini` et `infos.yml`, même si l'exécution échoue après leur génération. L'inventaire contient l'adresse et le compte de la VM : réservez son accès aux participants de l'atelier. Aucun fichier secret n'est publié.

| Essai | Résultat attendu |
| --- | --- |
| Configuration correcte | Trois sorties et récapitulatif sans échec |
| Hôte contenant un espace | Rejet de validation avant connexion |
| Port supérieur à 65535 | Rejet de validation |
| Mauvaise clé SSH | Échec de connexion, sans ignorer le contrôle |
| Python absent sur la VM | Échec à corriger sur la cible |

Ce support ne prétend pas qu'Ansible a été installé ou exécuté pendant sa rédaction. La syntaxe du playbook, ses dépendances et la connexion doivent aussi être éprouvées dans votre environnement.

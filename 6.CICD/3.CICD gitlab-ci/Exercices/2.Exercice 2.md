# Exercice 2 — Configuration selon l'environnement

## Objectif

Choisir `dev`, `staging` ou `prod`, calculer sa configuration et n'inclure que le job de simulation correspondant. Adaptation de l'[exercice Jenkins 2](../../2.CICD%20jenkins/Exercices/2.Exercice%202.md).

## Prérequis

[Guide commun](readme.md), puis notions d'[inputs](../2.environnement%20et%20params.md) et d'[artefacts](../7.artefact.md).

## Travail demandé

1. Déclarer l'input `cible` avec les trois options autorisées.
2. Créer un job `preparer_configuration`.
3. Utiliser un `case` shell pour calculer `EXO_API_URL` et `EXO_DB_NAME`.
4. Écrire ces valeurs non secrètes dans `configuration.env` et le publier en rapport `dotenv`.
5. Déclarer trois jobs de simulation, un pour chaque cible.
6. Choisir le job avec `rules` à partir de l'input déjà connu.
7. Dans ce job, lire la configuration transmise et afficher le comportement choisi.

Les URL et noms de base sont fictifs. Ne créez pas de base de données et ne contactez pas les URL.

## Divergences à prendre en compte

Un `export` du job de préparation n'est pas une variable globale persistante. Le rapport dotenv transmet les données aux jobs suivants.

Les `rules` sont évaluées avant le calcul du dotenv : elles doivent utiliser l'input, pas les variables qui seront produites par le script. Le job non retenu n'est pas ajouté au pipeline.

## Critères de réussite

| Cible | Job de simulation présent | Configuration attendue |
| --- | --- | --- |
| `dev` | `simuler_dev` | URL dev et base dev |
| `staging` | `simuler_staging` | URL staging et base staging |
| `prod` | `simuler_prod` | URL prod et base prod |

Une cible hors liste doit être rejetée par la validation de l'input. Le script conserve aussi un cas d'erreur explicite.

## Livrables

Le YAML, les trois graphes de pipeline et le contenu non secret du dotenv.

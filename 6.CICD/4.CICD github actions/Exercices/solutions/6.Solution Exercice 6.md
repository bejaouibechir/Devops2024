# Solution 6 — Diagnostics SSH

[Énoncé](../6.Exercice%206.md) · [Préparation SSH](../readme.md#préparation-ssh-pour-les-exercices-6-à-8)

## 1. Workflow complet

Configurer l'environnement `atelier-ssh` et ses cinq valeurs avant l'exécution. Les exemples visent un lancement manuel sur `main` et un runner GitHub hébergé. OpenSSH et Python 3 sont présents sur l'image Ubuntu choisie ; l'étape de préparation contrôle leur disponibilité.

Créer `.github/workflows/exercice-6.yml` :

```yaml
name: Exercice 6 - Diagnostics SSH
# Déclare les événements qui peuvent lancer ce workflow.
on:
  # Autorise le lancement manuel avec les inputs éventuellement déclarés.
  workflow_dispatch:

# Limite les droits du GITHUB_TOKEN pour la portée du workflow ou du job.
permissions: {}
# Définit les réglages par défaut des commandes run dans cette portée.
defaults:
  # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
  run:
    # Choisit l'interpréteur des commandes ; adapter leur syntaxe si ce shell change.
    shell: bash

# Déclare les jobs ; leur ordre dans le fichier ne crée pas de dépendance.
jobs:
  # Déclare le job « diagnostiquer » ; needs permet de préciser ses dépendances.
  diagnostiquer:
    # Conditionne l'exécution à cette expression évaluée par GitHub.
    if: ${{ github.ref == 'refs/heads/main' }}
    # Associe le job à l'environnement et à ses secrets ou règles de protection.
    environment: atelier-ssh
    # Sélectionne la machine qui exécutera ce job.
    runs-on: ubuntu-24.04
    # Arrête le traitement si sa durée dépasse ce nombre de minutes.
    timeout-minutes: 10
    # Injecte des variables dans les commandes de cette portée ; ce n'est pas un stockage partagé entre jobs.
    env:
      SSH_HOST: ${{ vars.SSH_HOST }}
      SSH_USER: ${{ vars.SSH_USER }}
      SSH_PORT: ${{ vars.SSH_PORT || '22' }}
    # Exécute les étapes de ce job dans l'ordre sur le même runner.
    steps:
      - name: Preparer les fichiers SSH
        # Injecte des variables dans les commandes de cette portée ; ce n'est pas un stockage partagé entre jobs.
        env:
          EXO_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          EXO_KNOWN_HOSTS: ${{ secrets.SSH_KNOWN_HOSTS }}
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Vérifie que l'outil est disponible sur le runner avant les opérations suivantes.
          command -v ssh
          command -v scp
          # Exécute ce programme Python localement pour valider les données et préparer les fichiers du job.
          python3 - <<'PY'
          import os
          import re
          # Lit les paramètres transmis au programme par l'environnement du job.
          host = os.environ["SSH_HOST"]
          user = os.environ["SSH_USER"]
          port = os.environ["SSH_PORT"]
          # Refuse une valeur qui pourrait sortir du format prévu ou modifier la structure de l'inventaire.
          if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9.-]*", host):
              raise SystemExit("Hote invalide : utiliser DNS ou IPv4 simple")
          if not re.fullmatch(r"[a-z_][a-z0-9_-]*", user):
              raise SystemExit("Compte SSH invalide pour cet atelier")
          if not re.fullmatch(r"[0-9]{1,5}", port) or not 1 <= int(port) <= 65535:
              raise SystemExit("Port invalide")
          PY
          # Interrompt le script si cette configuration obligatoire est absente ou vide.
          : "${EXO_PRIVATE_KEY:?Configurer SSH_PRIVATE_KEY}"
          : "${EXO_KNOWN_HOSTS:?Configurer SSH_KNOWN_HOSTS}"
          # Retire les permissions des autres utilisateurs lors de la création des fichiers suivants.
          umask 077
          # Prépare le répertoire utilisé par les fichiers de cette étape.
          mkdir -p "$RUNNER_TEMP/atelier-ssh"
          # Applique les permissions indiquées au fichier ou au répertoire avant son utilisation.
          chmod 700 "$RUNNER_TEMP/atelier-ssh"
          # Écrit ces données dans le fichier indiqué pour une étape ultérieure.
          printf '%s\n' "$EXO_PRIVATE_KEY" > "$RUNNER_TEMP/atelier-ssh/key"
          printf '%s\n' "$EXO_KNOWN_HOSTS" > "$RUNNER_TEMP/atelier-ssh/known_hosts"
          # Applique les permissions indiquées au fichier ou au répertoire avant son utilisation.
          chmod 600 "$RUNNER_TEMP/atelier-ssh/key" "$RUNNER_TEMP/atelier-ssh/known_hosts"
          {
            # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
            printf 'SSH_PRIVATE_KEY_FILE=%s\n' "$RUNNER_TEMP/atelier-ssh/key"
            printf 'SSH_KNOWN_HOSTS_FILE=%s\n' "$RUNNER_TEMP/atelier-ssh/known_hosts"
          # Rend ces variables disponibles aux étapes suivantes de ce job, pas aux autres jobs.
          } >> "$GITHUB_ENV"
      - name: Lire les informations distantes
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Exécute les commandes sur la VM ; les options SSH ci-dessous règlent la clé, le port et la vérification d'hôte.
          ssh -T -i "$SSH_PRIVATE_KEY_FILE" -p "$SSH_PORT" \
            -o BatchMode=yes -o IdentitiesOnly=yes \
            -o StrictHostKeyChecking=yes \
            -o UserKnownHostsFile="$SSH_KNOWN_HOSTS_FILE" \
            -o ConnectTimeout=10 \
            "$SSH_USER@$SSH_HOST" 'sh -se' <<'REMOTE'
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf '\nUtilisateur :\n'
          # Affiche le compte qui exécute la commande sur cette machine.
          whoami
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf '\nMachine :\n'
          # Affiche le nom de la machine où cette commande s'exécute.
          hostname
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf '\nDisponibilite :\n'
          # Affiche la durée de fonctionnement et la charge de la machine.
          uptime
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf '\nDisques :\n'
          # Affiche l'espace utilisé et disponible sur les systèmes de fichiers.
          df -h
          REMOTE
      - name: Nettoyer les fichiers secrets locaux
        # Autorise cette étape ou ce job même après échec ; le nettoyage reste soumis à la disponibilité du runner.
        if: ${{ always() }}
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Nettoie uniquement les chemins explicitement indiqués après leur utilisation.
          rm -f -- "$RUNNER_TEMP/atelier-ssh/key" "$RUNNER_TEMP/atelier-ssh/known_hosts"
          # Choisit la suite du traitement selon le résultat de ce test.
          if [[ -d "$RUNNER_TEMP/atelier-ssh" ]]; then
            # Nettoie uniquement les chemins explicitement indiqués après leur utilisation.
            rmdir -- "$RUNNER_TEMP/atelier-ssh"
          fi
```

## 2. Fichiers secrets et étapes

La première étape valide les paramètres et écrit la clé et known_hosts dans un répertoire temporaire privé. Elle inscrit **les chemins**, pas les secrets, dans `GITHUB_ENV`, pour les étapes suivantes du même job. Les deux secrets ne sont injectés que dans cette étape de préparation.

Les options SSH interdisent la demande de mot de passe et imposent la clé d'hôte attendue. `-T` évite un terminal interactif ; `sh -se` lit le heredoc sur la VM et interrompt sur erreur. Les commandes ne demandent pas sudo. Aucun plugin Jenkins ou action SSH tierce n'est nécessaire. [Client SSH](https://man.openbsd.org/ssh)

## 3. Différences avec GitLab

Une variable File GitLab fournissait déjà un chemin utilisable par `ssh -i`. Ici, un secret est du texte et doit être matérialisé. `GITHUB_ENV` persiste les chemins entre étapes, pas entre jobs.

Le job utilise l'environnement GitHub `atelier-ssh`. Sa restriction de branche complète le `if` du workflow ; elle doit être configurée dans l'interface, car une personne pouvant modifier le YAML peut aussi modifier ce `if`.

## 4. Essais et diagnostic

Les valeurs affichées doivent correspondre à la VM. Un port inaccessible entraîne un échec réseau ; une mauvaise clé d'hôte entraîne un refus d'identité. Réparer le réglage à partir d'une source fiable, sans désactiver le contrôle.

Le nettoyage final vise seulement les deux fichiers créés et leur répertoire. `always()` est une tentative de nettoyage après succès ou échec, sans garantie après perte du runner. Avec les runners hébergés, la VM du job est éphémère ; un runner persistant exige une politique de nettoyage et d'isolation supplémentaire.

| Symptôme | Vérification |
| --- | --- |
| Job ignoré | Branche sélectionnée différente de `main` |
| Secret absent | Environnement, nom du secret et droits d'accès |
| Permission denied | Compte, clé publique autorisée et clé privée |
| Host key verification failed | Hôte, port et known_hosts validé |
| Connection timed out | Pare-feu, routage et accessibilité depuis GitHub |

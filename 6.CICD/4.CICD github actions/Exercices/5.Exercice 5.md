# Exercice 5 — Traitement nocturne paramétrable

## Objectif

Simuler chaque nuit à 2 h, heure de Paris, un déploiement avec `API_URL`, `DB_NAME` et `NOTIFY`. Permettre aussi un essai manuel. Reprise de l'[exercice GitLab 5](../../3.CICD%20gitlab-ci/Exercices/5.Exercice%205.md).

## Travail demandé

1. Déclarer `workflow_dispatch` avec une cible et `schedule` avec fuseau explicite.
2. Configurer la variable de dépôt `NIGHTLY_TARGET`, valant `dev` pour commencer.
3. Choisir l'input pour le lancement manuel et cette variable pour la planification.
4. Calculer la configuration et la transmettre par outputs.
5. Simuler le déploiement puis une notification uniquement après succès.
6. Produire un résumé dans l'interface GitHub ; n'envoyer aucun email réel.

## Divergences

Le schedule est versionné dans le workflow GitHub et s'exécute sur la branche par défaut. GitLab conserve le schedule dans ses réglages avec sa propre cible et ses inputs. Les inputs de `workflow_dispatch` ne sont pas renseignés par un événement `schedule` : prévoir une source distincte.

## Critères et livrables

Tester manuellement les trois cibles, puis observer un lancement planifié. La cible manuelle doit rester prioritaire pour un lancement manuel. Une valeur invalide de `NIGHTLY_TARGET` doit échouer en préparation. Fournir workflow, réglage de variable et traces ; désactiver le schedule après l'atelier.

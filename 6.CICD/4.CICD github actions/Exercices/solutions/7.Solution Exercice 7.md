# Solution 7 — Script distant et artefacts

[Énoncé](../7.Exercice%207.md) · [Préparation SSH](../readme.md#préparation-ssh-pour-les-exercices-6-à-8)

## 1. Workflow complet

Configurer l'environnement `atelier-ssh` et ses cinq valeurs avant l'exécution. Les exemples visent un lancement manuel sur `main` et un runner GitHub hébergé. OpenSSH et Python 3 sont présents sur l'image Ubuntu choisie ; l'étape de préparation contrôle leur disponibilité.

Créer `.github/workflows/exercice-7.yml` :

```yaml
name: Exercice 7 - Script distant et artefacts
# Déclare les événements qui peuvent lancer ce workflow.
on:
  # Autorise le lancement manuel avec les inputs éventuellement déclarés.
  workflow_dispatch:

# Limite les droits du GITHUB_TOKEN pour la portée du workflow ou du job.
permissions: {}
# Définit les réglages par défaut des commandes run dans cette portée.
defaults:
  # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
  run:
    # Choisit l'interpréteur des commandes ; adapter leur syntaxe si ce shell change.
    shell: bash

# Déclare les jobs ; leur ordre dans le fichier ne crée pas de dépendance.
jobs:
  # Déclare le job « executer_script » ; needs permet de préciser ses dépendances.
  executer_script:
    # Conditionne l'exécution à cette expression évaluée par GitHub.
    if: ${{ github.ref == 'refs/heads/main' }}
    # Associe le job à l'environnement et à ses secrets ou règles de protection.
    environment: atelier-ssh
    # Sélectionne la machine qui exécutera ce job.
    runs-on: ubuntu-24.04
    # Arrête le traitement si sa durée dépasse ce nombre de minutes.
    timeout-minutes: 10
    # Injecte des variables dans les commandes de cette portée ; ce n'est pas un stockage partagé entre jobs.
    env:
      SSH_HOST: ${{ vars.SSH_HOST }}
      SSH_USER: ${{ vars.SSH_USER }}
      SSH_PORT: ${{ vars.SSH_PORT || '22' }}
    # Exécute les étapes de ce job dans l'ordre sur le même runner.
    steps:
      - name: Preparer les fichiers SSH
        # Injecte des variables dans les commandes de cette portée ; ce n'est pas un stockage partagé entre jobs.
        env:
          EXO_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          EXO_KNOWN_HOSTS: ${{ secrets.SSH_KNOWN_HOSTS }}
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Vérifie que l'outil est disponible sur le runner avant les opérations suivantes.
          command -v ssh
          command -v scp
          # Exécute ce programme Python localement pour valider les données et préparer les fichiers du job.
          python3 - <<'PY'
          import os
          import re
          # Lit les paramètres transmis au programme par l'environnement du job.
          host = os.environ["SSH_HOST"]
          user = os.environ["SSH_USER"]
          port = os.environ["SSH_PORT"]
          # Refuse une valeur qui pourrait sortir du format prévu ou modifier la structure de l'inventaire.
          if not re.fullmatch(r"[A-Za-z0-9][A-Za-z0-9.-]*", host):
              raise SystemExit("Hote invalide : utiliser DNS ou IPv4 simple")
          if not re.fullmatch(r"[a-z_][a-z0-9_-]*", user):
              raise SystemExit("Compte SSH invalide pour cet atelier")
          if not re.fullmatch(r"[0-9]{1,5}", port) or not 1 <= int(port) <= 65535:
              raise SystemExit("Port invalide")
          PY
          # Interrompt le script si cette configuration obligatoire est absente ou vide.
          : "${EXO_PRIVATE_KEY:?Configurer SSH_PRIVATE_KEY}"
          : "${EXO_KNOWN_HOSTS:?Configurer SSH_KNOWN_HOSTS}"
          # Retire les permissions des autres utilisateurs lors de la création des fichiers suivants.
          umask 077
          # Prépare le répertoire utilisé par les fichiers de cette étape.
          mkdir -p "$RUNNER_TEMP/atelier-ssh"
          # Applique les permissions indiquées au fichier ou au répertoire avant son utilisation.
          chmod 700 "$RUNNER_TEMP/atelier-ssh"
          # Écrit ces données dans le fichier indiqué pour une étape ultérieure.
          printf '%s\n' "$EXO_PRIVATE_KEY" > "$RUNNER_TEMP/atelier-ssh/key"
          printf '%s\n' "$EXO_KNOWN_HOSTS" > "$RUNNER_TEMP/atelier-ssh/known_hosts"
          # Applique les permissions indiquées au fichier ou au répertoire avant son utilisation.
          chmod 600 "$RUNNER_TEMP/atelier-ssh/key" "$RUNNER_TEMP/atelier-ssh/known_hosts"
          {
            # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
            printf 'SSH_PRIVATE_KEY_FILE=%s\n' "$RUNNER_TEMP/atelier-ssh/key"
            printf 'SSH_KNOWN_HOSTS_FILE=%s\n' "$RUNNER_TEMP/atelier-ssh/known_hosts"
          # Rend ces variables disponibles aux étapes suivantes de ce job, pas aux autres jobs.
          } >> "$GITHUB_ENV"
      - name: Generer le script
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Écrit le script sans substitution locale grâce au délimiteur cité ; ses commandes s'exécuteront plus tard.
          cat > infos.sh <<'SCRIPT'
          #!/usr/bin/env bash
          set -euo pipefail
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf 'Date UTC : '
          # Affiche l'heure demandée pour situer cette étape dans les journaux.
          date -u
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf 'Utilisateur : '
          # Affiche le compte qui exécute la commande sur cette machine.
          whoami
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf 'Machine : '
          # Affiche le nom de la machine où cette commande s'exécute.
          hostname
          SCRIPT
      - name: Transferer et executer
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Refuse un identifiant hors du format attendu avant de construire un chemin ou une commande.
          [[ "$GITHUB_RUN_ID" =~ ^[0-9]+$ ]]
          [[ "$GITHUB_RUN_ATTEMPT" =~ ^[0-9]+$ ]]
          # Prépare une valeur locale au shell ; elle ne devient pas automatiquement disponible dans un autre job.
          remote_dir="/tmp/github-actions-${GITHUB_RUN_ID}-${GITHUB_RUN_ATTEMPT}"
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf 'Dossier distant : %s\n' "$remote_dir"
          # Centralise les options SSH pour appliquer la même identité et le même contrôle d'hôte à chaque appel.
          ssh_ci() {
            # Exécute les commandes sur la VM ; les options SSH ci-dessous règlent la clé, le port et la vérification d'hôte.
            ssh -T -i "$SSH_PRIVATE_KEY_FILE" -p "$SSH_PORT" \
              -o BatchMode=yes -o IdentitiesOnly=yes \
              -o StrictHostKeyChecking=yes \
              -o UserKnownHostsFile="$SSH_KNOWN_HOSTS_FILE" \
              -o ConnectTimeout=10 "$SSH_USER@$SSH_HOST" "$@"
          }
          # Crée sur la VM le répertoire propre à cette exécution ; un dossier existant doit faire échouer cet appel.
          ssh_ci "umask 077; mkdir '$remote_dir'"
          # Transfère le fichier vers la VM ; -P désigne le port SSH pour scp.
          scp -i "$SSH_PRIVATE_KEY_FILE" -P "$SSH_PORT" \
            -o BatchMode=yes -o IdentitiesOnly=yes \
            -o StrictHostKeyChecking=yes \
            -o UserKnownHostsFile="$SSH_KNOWN_HOSTS_FILE" \
            -o ConnectTimeout=10 \
            infos.sh "$SSH_USER@$SSH_HOST:$remote_dir/infos.sh"
          # Rend le script distant exécutable, puis le lance sur la VM et conserve son code de retour.
          ssh_ci "chmod 700 '$remote_dir/infos.sh' && '$remote_dir/infos.sh'" \
            > execution-distante.log 2>&1
          # Affiche le contenu ou la liste des fichiers pour vérifier le résultat de l'étape précédente.
          cat execution-distante.log
          # Supprime sur la VM uniquement le fichier de cette tentative, puis son répertoire devenu vide.
          ssh_ci "rm -- '$remote_dir/infos.sh' && rmdir -- '$remote_dir'"
      - name: Conserver le script et le journal
        # Autorise cette étape ou ce job même après échec ; le nettoyage reste soumis à la disponibilité du runner.
        if: ${{ always() }}
        # Publie les fichiers indiqués pour les conserver après le job.
        uses: actions/upload-artifact@v7
        # Fournit les paramètres attendus par l'action ou le workflow appelé.
        with:
          name: exercice-7-${{ github.run_id }}-${{ github.run_attempt }}
          path: |
            infos.sh
            execution-distante.log
          # Demande cette durée de conservation pour l'artefact, dans les limites du dépôt.
          retention-days: 1
          # Règle le résultat de l'upload lorsqu'aucun fichier ne correspond au chemin.
          if-no-files-found: warn
      - name: Nettoyer les fichiers secrets locaux
        # Autorise cette étape ou ce job même après échec ; le nettoyage reste soumis à la disponibilité du runner.
        if: ${{ always() }}
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Le shell arrête sur une commande en échec hors tests conditionnels, refuse une variable non définie, propage aussi les erreurs dans les pipelines de commandes.
          set -euo pipefail
          # Nettoie uniquement les chemins explicitement indiqués après leur utilisation.
          rm -f -- "$RUNNER_TEMP/atelier-ssh/key" "$RUNNER_TEMP/atelier-ssh/known_hosts"
          # Choisit la suite du traitement selon le résultat de ce test.
          if [[ -d "$RUNNER_TEMP/atelier-ssh" ]]; then
            # Nettoie uniquement les chemins explicitement indiqués après leur utilisation.
            rmdir -- "$RUNNER_TEMP/atelier-ssh"
          fi
```

## 2. Où s'exécutent les commandes ?

Le heredoc `<<'SCRIPT'` produit un fichier sans substitution locale. Les commandes `date`, `whoami` et `hostname` ne s'exécutent qu'après le transfert, sur la VM.

Le chemin distant contient deux identifiants numériques vérifiés. Il reste spécifique à cette exécution et à sa tentative. Le `mkdir` sans `-p` refuse de réutiliser un dossier existant. SSH utilise `-p` pour le port ; SCP utilise `-P`. Le serveur doit accepter le mode de transfert utilisé par son client SCP, généralement SFTP sur les versions récentes. [Client SCP](https://man.openbsd.org/scp)

La sortie distante est redirigée vers un fichier. Avec `set -e`, un statut distant non nul fait échouer l'étape ; l'upload ultérieur ne transforme pas ce statut en réussite.

## 3. Artefacts et nettoyage

`upload-artifact` publie les deux chemins explicitement nommés. `always()` permet de conserver un journal d'échec si le fichier a été créé. Si la préparation échoue avant la génération, l'absence de fichiers ne produit qu'un avertissement ; l'échec initial reste visible.

L'artefact porte un nom propre à l'exécution et reste un jour, sous réserve de la politique du dépôt. Les clés sont hors de ces chemins. Les droits exécutables du script ne sont pas garantis par une archive téléchargée : refaire un `chmod` avant un usage ultérieur. [Action upload-artifact](https://github.com/actions/upload-artifact)

Le nettoyage distant a lieu après succès. Si le transfert ou l'exécution échoue, inspecter le chemin exact affiché et supprimer seulement les fichiers de cette tentative après diagnostic. Éviter un nettoyage global de `/tmp`. Le nettoyage local s'exécute aussi après un échec ordinaire ; un arrêt brutal peut l'empêcher.

## 4. Comparaison et essais

Dans GitLab, `artifacts:when:always` et `artifacts:paths` déclaraient la collecte. Ici, c'est une étape séparée utilisant une action. Contrairement à une variable d'environnement, un artefact est un fichier à télécharger ; un éventuel autre job aurait besoin d'une action de téléchargement.

Après succès, télécharger l'artefact et vérifier le script, les valeurs de la VM et l'absence de secrets. Pour simuler un échec distant, ajouter temporairement `exit 1` à la fin du heredoc `SCRIPT` : le job doit échouer et conserver le journal disponible.

# Exercice 8 — Collecter des informations avec Ansible

## Objectif

Générer un inventaire et un playbook, puis exécuter Ansible depuis le runner pour interroger la VM par SSH. Adaptation de l'[exercice Jenkins 8](../../2.CICD%20jenkins/Exercices/8.Exercice%208.md).

## Architecture

Le runner est le **nœud de contrôle Ansible temporaire**. Le playbook est lu et orchestré dans le job ; ses tâches s'exécutent sur la VM. Il n'est pas nécessaire d'installer Ansible sur cette VM.

## Prérequis

Réussir l'exercice 6. Pour le corrigé proposé : Python 3.12 côté contrôle et Python 3.9 à 3.14 sur la VM, accessible sous `/usr/bin/python3`. Le compte SSH n'a pas besoin de sudo.

## Travail demandé

1. Préparer le client SSH et `ansible-core` dans le job.
2. Générer `inventory.ini` à partir de `SSH_HOST`, `SSH_USER` et `SSH_PORT`.
3. Garder la clé privée dans sa variable File ; ne pas créer `id_rsa` dans le dépôt.
4. Générer `infos.yml` avec les tâches `date`, `whoami` et `hostname`.
5. Utiliser `ansible.builtin.command`, enregistrer les résultats et les afficher avec `debug`.
6. Marquer ces commandes de consultation `changed_when: false`.
7. Vérifier la syntaxe du playbook, puis exécuter `ansible-playbook`.
8. Garder la vérification de clé d'hôte active.

## Divergences et corrections

Les opérations ne passent par aucun plugin Jenkins ou GitLab. La CLI Ansible utilise la clé du job pour établir les connexions.

`command` suffit puisque les tâches ne nécessitent ni pipe ni redirection shell. Un résultat enregistré doit être affiché explicitement pour rendre les informations visibles dans le journal.

La validation `--syntax-check` ne prouve pas que la VM est joignable : l'exécution réelle reste un contrôle séparé.

## Critères de réussite

- L'inventaire vise la VM attendue.
- Le playbook est valide et les trois valeurs sont visibles.
- Le récapitulatif montre `failed=0`, `unreachable=0`, `changed=0`.
- Aucun secret n'est commité ni publié en artefact.
- Une clé d'hôte invalide ou un compte SSH incorrect provoque un échec.

## Livrables

Le YAML CI, l'inventaire sans secret, le playbook et le récapitulatif Ansible.

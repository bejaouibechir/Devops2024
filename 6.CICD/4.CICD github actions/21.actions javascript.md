# Créer une action JavaScript

## Objectif

Encapsuler une logique Node.js dans une action réutilisable, avec ses métadonnées, ses inputs et ses outputs.

## 1. Différence avec une composite

Une composite assemble des étapes. Une action JavaScript exécute un programme avec le runtime Node indiqué dans `action.yml`.

Le runner fournit ce runtime à l'action : il ne faut pas ajouter `setup-node` uniquement pour démarrer celle-ci. Ses dépendances doivent toutefois faire partie de la distribution de l'action. [Création d'actions JavaScript](https://docs.github.com/en/actions/tutorials/create-actions/create-a-javascript-action)

Cet atelier utilise uniquement un module standard Node, sans installation npm.

## 2. Métadonnées

Créez `.github/actions/version-js/action.yml` :

```yaml
name: Version JavaScript
description: Calcule une version a partir d'un prefixe valide
inputs:
  prefix:
    description: Deux composantes numeriques
    required: true
    default: '1.0'
outputs:
  version:
    description: Version calculee
runs:
  using: node24
  main: index.cjs
```

Le suffixe `.cjs` rend le mode CommonJS explicite, même si le dépôt applicatif utilise des modules ESM.

## 3. Programme de l'action

Créez `.github/actions/version-js/index.cjs` :

```javascript
const { appendFileSync } = require('node:fs');

try {
  const prefix = process.env.INPUT_PREFIX || '';
  const runNumber = process.env.GITHUB_RUN_NUMBER || '';
  const outputFile = process.env.GITHUB_OUTPUT;

  if (!/^\d+\.\d+$/.test(prefix)) {
    throw new Error('Le prefixe doit avoir la forme 1.0');
  }
  if (!/^\d+$/.test(runNumber) || !outputFile) {
    throw new Error('Contexte GitHub Actions incomplet');
  }

  const version = `${prefix}.${runNumber}`;
  appendFileSync(outputFile, `version=${version}\n`, 'utf8');
  console.log('Version calculee avec succes');
} catch (error) {
  console.error(error.message);
  process.exitCode = 1;
}
```

Le runner fournit l'input simple `prefix` à ce programme dans `INPUT_PREFIX`. La sortie est écrite dans le fichier `GITHUB_OUTPUT`, et une exception donne un statut d'échec.

L'output ne contient ici que chiffres et points. Pour des données multiligne, utilisez le protocole approprié ou le toolkit `@actions/core`, au lieu de concaténer sans précaution des entrées arbitraires.

## 4. Workflow appelant

Créez `.github/workflows/javascript-action.yml` :

```yaml
name: Tester une action JavaScript
on:
  workflow_dispatch:
permissions:
  contents: read
jobs:
  demo:
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v7
        with:
          persist-credentials: false
      - id: version
        uses: ./.github/actions/version-js
        with:
          prefix: '4.2'
      - env:
          VERSION: ${{ steps.version.outputs.version }}
        run: |
          printf 'Version : %s\n' "$VERSION"
```

**Résultat attendu :** `4.2.N`. Une entrée invalide doit faire échouer l'action.

## 5. Distribuer une action avec dépendances

Si vous ajoutez des packages npm, le runner ne lance pas automatiquement `npm install` dans l'action téléchargée. Préparez une distribution incluant les dépendances, par exemple un bundle, et versionnez le fichier exécuté avec le code source et le lockfile.

Testez les systèmes annoncés compatibles et gardez un runner autonome compatible avec le runtime déclaré. Les actions JavaScript ne sont pas limitées à Linux comme les actions Docker.

## Exercice

Testez un préfixe valide puis `abc`. Ajoutez un second output contenant uniquement le numéro d'exécution et exposez-le dans le workflow.

L'action n'a pas été publiée ni exécutée sur GitHub pendant la rédaction.

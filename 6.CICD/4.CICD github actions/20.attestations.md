# Attester la provenance d'un artefact

## Objectif

Associer un fichier construit à une preuve vérifiable de son origine dans GitHub Actions.

## 1. Checksum et attestation

Un checksum détecte une différence de contenu. Une attestation de provenance associe le digest à des informations sur le processus de construction et à une identité vérifiable.

La provenance et la signature existent aussi dans d'autres plateformes, dont GitLab. Cette fiche traite l'intégration GitHub : permissions, action d'attestation, stockage et vérification avec GitHub CLI.

Une attestation ne certifie ni l'absence de vulnérabilité ni la qualité des tests. Le consommateur doit vérifier que l'identité et le processus indiqués sont ceux qu'il accepte.

## 2. Prérequis

Les attestations sont disponibles sur les dépôts publics avec les offres actuelles. Pour les dépôts privés/internes, la fonctionnalité nécessite GitHub Enterprise Cloud selon la documentation consultée. Vérifiez votre offre avant l'essai. [Disponibilité et utilisation](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations/use-artifact-attestations)

## 3. Workflow complet

Fichier `.github/workflows/attestation.yml` :

```yaml
name: Attester un fichier
on:
  workflow_dispatch:
permissions: {}
jobs:
  build:
    if: ${{ github.ref == 'refs/heads/main' }}
    runs-on: ubuntu-24.04
    permissions:
      contents: read
      id-token: write
      attestations: write
    steps:
      - uses: actions/checkout@v7
        with:
          persist-credentials: false
      - name: Produire le fichier de demonstration
        run: |
          mkdir -p dist
          printf 'Commit source : %s\n' "$GITHUB_SHA" > dist/livrable.txt
      - name: Attester la provenance
        uses: actions/attest@v4
        with:
          subject-path: dist/livrable.txt
      - name: Conserver le fichier
        uses: actions/upload-artifact@v7
        with:
          name: livrable-atteste
          path: dist/livrable.txt
          if-no-files-found: error
```

**Résultat attendu :** un fichier téléchargeable et une attestation de sa provenance. L'upload conserve le fichier ; l'attestation porte sur son contenu et n'est pas un remplacement de l'upload. [Action attest](https://github.com/actions/attest)

La documentation actuelle utilise `actions/attest@v4`. Vérifiez les migrations si votre dépôt utilise une ancienne action `attest-build-provenance`.

## 4. Vérifier côté consommateur

Après téléchargement et extraction de l'artefact, depuis un poste équipé de GitHub CLI authentifié :

```sh
gh attestation verify livrable.txt --repo ORGANISATION/DEPOT
```

Remplacez `ORGANISATION/DEPOT` par le dépôt producteur. Pour un processus de livraison, complétez la politique de vérification avec le workflow signataire et la référence attendue selon les options de votre version de `gh`.

Modifier le fichier après sa production doit rendre sa vérification incompatible avec l'attestation initiale. [Commande de vérification](https://cli.github.com/manual/gh_attestation_verify)

## 5. Images et SBOM

Pour une image de conteneur, on atteste un nom et un digest précis ; un tag mutable n'est pas une identité de contenu.

Une SBOM décrit des composants logiciels. L'attester signe une déclaration portant sur cet inventaire ; cela ne rend pas automatiquement l'inventaire complet ou exact.

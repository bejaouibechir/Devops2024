# Créer une action Docker

## Objectif

Distribuer une commande avec son environnement Linux dans une action conteneurisée.

## 1. Trois notions distinctes

| Notion | Fonction |
| --- | --- |
| `jobs.<id>.container` | Exécuter les commandes du job dans une image |
| Action Docker | Exécuter une étape réutilisable dans son conteneur |
| `services` | Démarrer une dépendance, par exemple une base de données |

GitLab sait utiliser des images et services, mais n'exécute pas nativement une action GitHub décrite par `runs.using: docker`.

Prérequis : runner Linux avec Docker. L'exemple utilise un runner Ubuntu hébergé. [Actions Docker](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-a-docker-container-action)

## 2. Métadonnées

Créez `.github/actions/version-docker/action.yml` :

```yaml
name: Version Docker
description: Calcule une version dans un conteneur
# Déclare les paramètres attendus ; leur type et leurs contraintes définissent le contrat.
inputs:
  # Définit le paramètre « prefix » et les contraintes de sa valeur.
  prefix:
    description: Deux composantes numeriques
    required: true
    # Fournit la valeur utilisée si cet input n'est pas renseigné.
    default: '1.0'
# Expose les valeurs produites pour les étapes, jobs ou workflows consommateurs selon cette portée.
outputs:
  version:
    description: Version calculee
# Décrit comment le runner exécute cette action réutilisable.
runs:
  # Choisit le type d'action et, pour JavaScript, son runtime Node.
  using: docker
  # Désigne l'image ou le Dockerfile à utiliser dans cette configuration de conteneur.
  image: Dockerfile
  # Transmet ces valeurs comme arguments à l'action conteneurisée.
  args:
    - ${{ inputs.prefix }}
```

L'input est passé comme argument, pas interpolé dans un programme shell.

## 3. Image et script

Créez `.github/actions/version-docker/Dockerfile` :

```dockerfile
# Choisit l'image Linux de base de l'action.
FROM alpine:3.22
# Ajoute le script de l'action dans l'image construite.
COPY entrypoint.sh /entrypoint.sh
# Prépare le fichier pendant la construction de l'image.
RUN chmod 755 /entrypoint.sh
# Définit la commande lancée quand GitHub démarre le conteneur de l'action.
ENTRYPOINT ["/entrypoint.sh"]
```

Créez `.github/actions/version-docker/entrypoint.sh` avec des fins de ligne LF :

```sh
#!/bin/sh
set -eu
# Utilise la valeur fournie ou sa valeur de repli si elle est absente ou vide.
prefix="${1:-}"
# Contrôle le format ou le contenu attendu avant d'utiliser cette donnée.
if ! printf '%s\n' "$prefix" | grep -Eq '^[0-9]+\.[0-9]+$'; then
  # Écrit le diagnostic sur la sortie d'erreur pour distinguer l'erreur des résultats normaux.
  echo "Prefixe invalide" >&2
  # Renvoie un statut non nul pour conserver l'échec dans le résultat du job.
  exit 1
fi
# Sélectionne le cas correspondant à la valeur ; la branche de repli traite les valeurs non prévues.
case "${GITHUB_RUN_NUMBER:-}" in
  ''|*[!0-9]*)
    # Écrit le diagnostic sur la sortie d'erreur pour distinguer l'erreur des résultats normaux.
    echo "Numero de run invalide" >&2
    # Renvoie un statut non nul pour conserver l'échec dans le résultat du job.
    exit 1
    ;;
esac
# Publie une sortie d'étape ; son exposition au niveau du job permet ensuite un échange via needs.
printf 'version=%s.%s\n' "$prefix" "$GITHUB_RUN_NUMBER" >> "$GITHUB_OUTPUT"
```

`chmod` dans l'image fixe le droit d'exécution. Le format LF évite une erreur d'interpréteur causée par des fins de ligne Windows. Pour une distribution figée, choisissez aussi un digest d'image de base vérifié.

## 4. Workflow appelant

Créez `.github/workflows/docker-action.yml` :

```yaml
name: Tester une action Docker
# Déclare les événements qui peuvent lancer ce workflow.
on:
  # Autorise le lancement manuel avec les inputs éventuellement déclarés.
  workflow_dispatch:
# Limite les droits du GITHUB_TOKEN pour la portée du workflow ou du job.
permissions:
  # Autorise l'accès au contenu du dépôt selon le niveau indiqué.
  contents: read
# Déclare les jobs ; leur ordre dans le fichier ne crée pas de dépendance.
jobs:
  # Déclare le job « demo » ; needs permet de préciser ses dépendances.
  demo:
    # Sélectionne la machine qui exécutera ce job.
    runs-on: ubuntu-24.04
    # Exécute les étapes de ce job dans l'ordre sur le même runner.
    steps:
      # Récupère les fichiers du dépôt dans le workspace du runner.
      - uses: actions/checkout@v7
        # Fournit les paramètres attendus par l'action ou le workflow appelé.
        with:
          # Choisit si checkout conserve l'authentification Git pour les commandes suivantes.
          persist-credentials: false
      - id: version
        # Appelle une action locale ; ses fichiers doivent déjà être présents après checkout.
        uses: ./.github/actions/version-docker
        # Fournit les paramètres attendus par l'action ou le workflow appelé.
        with:
          prefix: '5.0'
      # Injecte des variables dans les commandes de cette portée ; ce n'est pas un stockage partagé entre jobs.
      - env:
          VERSION: ${{ steps.version.outputs.version }}
        # Lance ce script dans le shell de l'étape ; un nouveau run ouvre un nouveau processus.
        run: |
          # Produit du texte sur la sortie standard, ou dans le fichier destinataire si le bloc est redirigé.
          printf 'Version : %s\n' "$VERSION"
```

**Résultat attendu :** `5.0.N`. GitHub construit l'image de l'action puis lance son point d'entrée.

## 5. Fichiers et durée de vie

Le workspace est monté pour permettre l'échange de fichiers avec le job. Un fichier créé ailleurs dans le système de fichiers du conteneur n'est pas automatiquement un résultat persistant.

La construction et le démarrage du conteneur ont un coût. Une petite logique portable peut être plus simple dans une action JavaScript ; une image est pertinente quand elle apporte les outils nécessaires.

## Exercice

Passez `5.x` en input : le script doit refuser la valeur et le job doit échouer. Comparez avec les variantes [composite](10.actions%20personnalisees.md) et [JavaScript](21.actions%20javascript.md) qui remplissent le même contrat.
